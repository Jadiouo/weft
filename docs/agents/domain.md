# Domain docs — 單一 context

## 佈局

| 檔案 | 角色 |
|---|---|
| `CONTEXT.md`（根目錄） | 詞彙表。這個專案的共用語言 |
| `docs/adr/` | 難以反轉的決策，一項一檔 |
| `docs/decisions.md` | 既有的決策記錄（D1–D31），**與 ADR 並存** |

> `docs/decisions.md` 早於本配置存在，且已累積 31 條，格式成熟
> （含「處置」與「教訓」段）。**不遷移。** 新的架構級決策寫進
> `docs/adr/`，實作級決策繼續寫 `decisions.md`。
> 兩者的分界：**ADR 是「為什麼選這條路」，D 是「做的時候發現什麼」。**

## 消費規則

動任何一個領域概念前：

1. 先讀 `CONTEXT.md`，用它既有的詞。**不要發明同義詞。**
2. 動到某個區域前，先看 `docs/adr/` 有沒有管到那個區域的決策，有就遵守。
3. 發現一個詞在做兩件事（或兩個詞在做同一件事）→ 這是領域模型的缺陷，
   用 `/domain-modeling` 處理，不要繞過。

## 這個專案的詞彙特別容易出問題的地方

歷史上出過事的都是**一個符號承載兩種語意**：

- `0.95` —— 同時是「per-video 閘門」（§5.4）與「全域驗收門檻」（§5.2），
  而 R27 算的是四支合計。三個不同的東西共用一個數字。
- `§1.3 profile` —— 同時是「範例」與「S-1 的比對基準」。
- `prompt_version` —— 同一個欄位名出現在 `S4aConfig` 與 `S4Config`，
  未錨定的字串替換同時改到兩個（D30）。

**新增任何門檻、基準、版本欄位時，先問：這個符號會不會被兩個地方
用成兩種意思？**
