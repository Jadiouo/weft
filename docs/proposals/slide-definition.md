# 提案：把「什麼算投影片」的定義收緊

狀態：**提案，未實作**。**我刻意沒有自己改標註**——
「改 ground truth 讓紅燈變綠」正是 §5.5 存在要防的事，即使理由充分。

提出日：2026-08-07
起因：B1 讓 §5.2 的分類門檻真的跑起來後紅燈（0.818 < 0.95）。

---

## 1. 錯誤 100% 集中在定義不清的地方

| 類別 | 準確率 |
|---|---|
| **核心**：全螢幕投影片 vs 純攝影棚講者鏡頭 | **33/33 = 100%** |
| **歧義類**：片頭片尾動畫、講者活鏡頭＋疊加文字 | **7/15 = 46.7%** |

三支影片、8 個錯誤，**沒有一個落在核心類**。

而且兩支影片錯的是**同一批**：`slide_002`（片頭 logo 動畫）、
`slide_008`（片頭標題動畫）、`slide_009`／`slide_010`（主講人簡介）。

歧義類的 46.7% 接近擲骰——**那不是模型不會，是題目沒有答案。**

## 2. 現行定義為什麼判不了

SDD §4.7a 的 prompt：

> **是投影片**：畫面主體為文字、圖表、經文、流程圖等準備好的教材內容。
> **不是投影片**：講者的攝影棚鏡頭、片頭片尾動畫、純裝飾畫面、會場全景。

**主講人簡介同時滿足兩邊**：畫面裡有講者的活鏡頭（→ 不是），
也有準備好的文字排版（→ 是）。定義沒說哪一邊優先。

**片頭標題卡**同樣：「古典醫學之人體設計系列」是為這個系列製作的，
算不算「準備好的教材內容」？

## 3. 提議的定義

**是投影片 ⟺ 兩個條件同時成立：**

1. 畫面主體是**為了講解本集內容**而製作的材料
2. 畫面主體**不是活的攝影機訊號**（講者、會場）

| 畫面 | 條件 1 | 條件 2 | 判定 | 與現況比 |
|---|---|---|---|---|
| 全螢幕經文／圖表 | ✓ | ✓ | **是** | 不變 |
| 攝影棚講者鏡頭 | ✗ | ✗ | 否 | 不變 |
| 章節標題卡（紅底「01生命之初」） | ✓ | ✓ | **是** | 不變 |
| **主講人簡介**（講者活鏡頭＋文字） | ✓ | **✗** | **否** | **改變**（原為是） |
| 片頭／片尾動畫 | **✗** | ✓ | 否 | 澄清 |
| 講堂全景 | ✗ | ✗ | 否 | 不變 |

## 4. 為什麼主講人簡介應該判「否」——**產品理由，不是分數理由**

這一點必須說清楚，否則就是「改定義讓測試過」：

1. **內容是講者的學經歷，不是本集的教學內容。** 進了知識庫是雜訊——
   使用者問「胎兒三個月時發生什麼」不該檢索到「中原大學工業系畢」。
2. **全系列 30 集完全相同。** 一份重複 30 次的內容對 RAG 只有稀釋作用。
3. **§5.4 驗不了它。** 講者不會唸自己的簡歷，逐字稿裡沒有對應內容；
   `slide_ocr` 型的 block 拿它當來源，溯源檢查形同虛設。
4. **條件 2 同時解決另一個風險**：R8 記過「疊加模式」的問題——
   投影片內容疊在講者畫面上時難以判定。這條規則給了明確答案：
   **有活鏡頭就不是投影片**，那些內容靠逐字稿承接。

第 4 點也是代價：若某系列真的大量使用「疊加」呈現教材，
這條規則會讓那些內容整批落到 `transcript` 來源。
**S-1 勘查必須把「疊加佔比」列入必測**，超標時中止並報告。

## 5. 若採納要改什麼

| 位置 | 改動 |
|---|---|
| SDD §4.7a 的 prompt | 兩條件的定義取代現行敘述 |
| `stages/slides.py` 的 `SYSTEM_PROMPT`／`CLASSIFY_SYSTEM` | 同上，並 bump `prompt_version` |
| `tests/golden/*.golden.json` | `slide_009`／`slide_010` 由 `true` 改 `false`，並在 notes 記明依據 |
| §5.1(B) 標註規範 | 新增第 8 條：「同時有活鏡頭與準備好的文字時，判否」 |
| SDD §9 | 新增風險：疊加式教材會整批落到 transcript 來源 |

**預期效果**：分類準確率 33/33 的核心不變，歧義類的一半錯誤消失。
但**不保證達到 0.95**——片頭片尾那一半仍需要條件 1 的判斷，
而「為了講解本集內容」對片頭標題卡仍有解釋空間。

**我沒有先算改完的分數**，因為那會讓這份提案看起來像在湊數字。
要採納就採納定義本身的道理，分數是後果不是理由。
