## 3. 驗收：人讀那半——27 支全部讀過

沒有人工字幕，**算不出 CER**，所以只能人讀、而且結論要標成非量化。

### 機械訊號先排除災難（這些是量化的）

| 指標 | 27 支的值 |
|---|---|
| 字/秒 | 4.16–5.27，中位 4.72——**全距很窄，沒有一支崩掉** |
| 最大 6-gram 重複 | 2–15，是講課口頭禪，不是 Whisper 的重複迴圈 |
| 全形標點密度 | **0.00%–0.17%，等於沒有標點** |
| 非中英字元 | 查過，幾乎全是半形 `?`，其餘 θ／α／β |

### 人讀的結論

27 支全部是連貫、切題、看得懂的中文。**而錯誤幾乎全屬同一類**：

| 逐字稿 | 應為 |
|---|---|
| `卡住的關係`／`卡坐標系` | 卡氏座標系 |
| `ControlRaw` | Control **Law** |
| `Inverse Jacobian Collision Control` | …**Compliance** Control |
| `Homogenetic Transformation` | Homogene**ous** |
| `determined j` | determinant J |
| `Effective Inertial` | Effective Inert**ia** |
| `彈音係數` | 彈簧係數 |
| `Learning my demonstration` | Learning **by** demonstration |
| `你的城市`（重複多次）| 你的**程式** |

**全部是專有名詞被聽成音近的非術語。**
這張表就是使用者第二層構想的實證基礎——**詞表就能修，不需要完整語料庫。**

## 4. 一個難堪的發現（R39）

糾錯機制**早就存在**（S4 拿投影片對照修同音錯字）。實測成績：

| | 支數 | corrections |
|---|---|---|
| 人工字幕 | 4 | **16** |
| Whisper | 27 | **0** |

**方向完全反了。** 乾淨的那批修了 16 筆，該修的那批一筆都沒有——
因為它們只跑到 S3，而**糾錯掛在 S4**。

> **糾錯掛錯了層。它掛在「理解」，而它修的是「逐字稿」。**

我一開始把這件事講成「糾錯那層在這批素材上等於沒作用」——**那句推論是錯的**，
當場更正：不是沒作用，是**還沒走到**。差別很重要，因為前者會讓人去改糾錯的
實作，後者指向的是它掛的位置。

## 5. 清 36 GB 之前先補的一行（D36／R38）

`02_frames` 的唯一下游是 `dedup.py` 的 `studio_distance` 診斷，
而它**算不出來就靜靜不寫任何欄位**——讀 `04_dedup.json` 的人分不出
「沒有 frames」與「距離剛好沒被記錄」。**與 D34 的 `video_pass_rate`
是同一類**。已改為明寫「未計算」。

查的過程順帶撞到一個更廣的洞：**`mark_stale`（state 說完成、產物卻不在）
在整個 repo 裡只被呼叫一次**，守 S4a。S1b／S1c 用的 `is_satisfied()`
只比對 `params_hash`，產物在不在它不看。這次沒變成災難（frames 的下游
只有那個診斷），**但修法要先有「哪些產物可拋」的分類，而那不存在——推到 v2**。

### 刪除本身沒有執行

`rm -rf work/*/02_frames` **被權限分類器擋下**。沒有繞過，留給使用者決定。
36 GB 仍在磁碟上，`docs/v1-scope.md` 與 D36 已寫成「決定要刪」而非「已刪」。

## 6. 使用者提的三層架構

> 「第二層是想辦法（爬蟲？）建一個這個主題的**有相對文字的先驗資料庫**，
> 再根據它去調整逐字稿。第三層才做成 RAG 或小模型的訓練資料。」

方向與文獻一致（RAG-ASR correction／contextual biasing／forced alignment
的共同點就是**修逐字稿、不修驗證**），也直接回應了 8/13 的架構批評。
四個銳化的點寫進 `v1-scope.md` §5.1，最重要的是第一個：

> **RAG 容忍雜訊，訓練不容忍。** 強 reader 自己會把
> `Learning my demonstration` 讀成 `by`；訓練會把它變成模型的信念。
> **因為終點是訓練，第二層是必要的，不是可選的優化。**
