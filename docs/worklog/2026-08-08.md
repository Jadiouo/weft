## 二、分類判準：五個版本，兩次被自己的量測打回來

起點是使用者的一句話：**「把主持人的介紹現在去除」**。

| 版本 | 判準 | 調校集 | 保留集 |
|---|---|---|---|

### v3 的 1.000 是假的——今天最值錢的發現

那三支影片全是攝影棚定鏡加全螢幕投影片輸出，
20 張正例**沒有一張看得到講者**。所以「有講者 → 不是」在上面 20/20 成立。
**它看起來像判準，其實是這批素材的統計巧合。**

我另外標了一支從沒跑過 S4a 的影片（第 14 集 肝臟）當保留集。
它是**講堂實景**——講者站在投影幕前，投影片是攝影機拍到的。
`slide_023`/`024` 左半是清楚可讀的肝門靜脈解剖圖、右半是講者本人，
兩張都是投影片。

**v3 在保留集上的錯誤恰好只有這兩張。**

> 一條在 20/20 上成立的規則，換一個場景就整組失效。
> 沒有保留集，1.000 會被當成問題解決了。

制度化：`GoldenAnnotation.holdout` 欄位，測試斷言「必須存在保留集」。
這是 §5.1(B) 第 4 條（提案演算法須與受測演算法不同）在 prompt 上的對應。

### 結論：改措辭已經到頂

到 v3 之後，分數的變動反映的已經是**模型對指令措辭的敏感度**。

## 三、溯源 0.838 拆開後，一半不是內容問題

167 個 block、通過 140。27 筆未通過拆解：

| 成因 | 筆數 |
|---|---|
| **歸屬錯**：內容溯得到**同一段的另一個**來源 | **15** |
| 兩個來源都對不上——真正要判內容的 | 10 |
| 來源投影片其實不是投影片（分類紅燈的下游） | 2 |

差距不是邊緣值：標錯的那個來源 containment 是 0.00–0.09，對的那個是 0.51–0.59。
模型把投影片上的內容摘要出來，卻標成「講者說的」。

**這兩件事修法完全不同**，混在一個數字裡就都看不見。
已做進 `_diagnose_wrong_source`，但**不自動改判為通過**——
§3.5 要求 chunk 自足，「投影片寫了 X」和「講者說了 X」在下游是兩件事。

那 10 筆再看，還有 4 筆是「書名／數字在投影片、不在該段逐字稿」，
跟歸屬錯是同一件事的另一面；1 筆是抽取器誤報（「**兩**大原因」的「兩」）。
**真正可能是內容問題的不到 5 筆。**

改 S4c 的 prompt 後：**歸屬錯 15 → 9，通過率 0.838 → 0.871**。
（block 總數掉了 7%，所以上升有一部分可能來自分母變小。）

## 四、換頁門檻第一次跑起來：F1 0.645，但漏抓是 0

標了一支影片的換頁時間點，42 個提案逐一開前後幀判讀，確認 10 個。

```
P=0.476  R=1.000  F1=0.645   (TP=10 FP=11 FN=0)
```

**S1b 找到了每一個標註的換頁**，11 個誤報**全部**在片頭（2–57s）
與片尾（936–949s）。

也就是說 F1 沒過的唯一原因是 S1b 也偵測到片頭片尾的場景切換——
而 D16 之後，「這是不是投影片」已經是 S4a 的責任，不是 S1b 的。
**這個指標把 S1b 沒有責任的事算在它頭上。**
沒動門檻（§5.5 #7），寫成待決事項。

標註時也修掉提案器的召回缺陷：原本「距上一個提案至少 4 秒」的壓制，
把 68–70 秒的交叉淡化整段吃掉，而那才是章節標題卡真正出現的地方。
**ground truth 漏抓比誤抓嚴重**——漏掉真實邊界會讓 S1b 正確找到它
反而被算成 FP，等於用錯的答案懲罰對的行為。

### 1. 循環論證，差點成立（R25）

`slide_groups` 的初版是**從 S1c 自己的輸出直接抄的**——
那是拿受測者的答案改考卷，§5.1(B) 第 4 條明文禁止。

同一個道理今天又用到一次：找「哪些是主講人簡介」時，
**不能拿模型的 `reject_reason` 去搜關鍵字**。
改用像素掃描——以人工確認過的一張為樣板，簡介頁 MAE ≤24.31、
次近者 ≥44.54，間隙 1.8x，命中恰好 5 張。

### 2. 改了 prompt 卻沒 bump 版本，差點下錯結論（D30）

`prompt_version: str = "vN"` 在兩個設定類別裡長得一模一樣，
未錨定的字串替換打到兩處。**第二次更糟**：它讓我改完 S4c 的 prompt 後
版本沒有變化 → 快取直接命中 → **新 prompt 從未被執行**，
溯源只動了 2 個 block。

我差一點就寫下「改寫來源歸屬的說明沒有用」。

防護：把 prompt 文字的雜湊釘在版本上。改文字 → 雜湊變 → 紅燈 →
必須同時改版本與期望值。已驗證擋得住。

### 3. 內容掉了 87%，管線一聲不吭（D31）

改 S4c prompt 的第一版寫了整整一段（含實測數字表格）解釋怎麼標來源，
還寫了「`provenance_ref` 隨便填」。`qwen2.5:14b` 被帶偏，
**投影片段落產出 0 個 content_block**，167 個 block 掉到 21 個。

**而每一項機械檢查都是綠的**——溯源通過率甚至更好看，因為分母小了。
管線照常產出一份少了 87% 內容的知識庫。

兩個教訓：
- 對 14B 模型，**prompt 的長度本身就是成本**。寫給人看的完整論證
  （為什麼、實測數字多少）放程式碼註解，不放 prompt。
- **不要告訴模型某個必填欄位「隨便填」**。要嘛拿掉它，要嘛認真要求它。

防護：投影片段落中 0 block 的比例超過 30% 即中止。
正常實測 0%、壞掉那次 70%。

## 八、方法論：今天驗證的東西

- **調校集上的滿分不是判準正確的證據。** 唯一的防線是拿一支沒參與調校的來測。
- **「邏輯上正確」與「模型判得出來」是兩回事。** v4 的判準涵蓋全部負例，
  但它要求的資訊（別集長什麼樣）根本不在模型的輸入裡。
  判準要用**模型看得見的東西**表達。
- **一個數字混了幾件事的時候，它會指向錯的修法。** 溯源 0.838 看起來像
  內容品質不夠，拆開後一半是歸屬與分類。
- **輸出「變少」不會自己報錯。** 而且分母變小還會讓比率型指標**更好看**。
- **ground truth 漏抓比誤抓嚴重。** 誤抓只是多一筆人工判掉；
  漏抓會讓正確的行為被算成錯的。
