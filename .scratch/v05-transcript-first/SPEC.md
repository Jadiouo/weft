# SPEC v0.5：逐字稿主幹化與收尾

2026-08-08。來源：`/grill-with-docs` 對話（2026-08-08）+
`docs/research/2026-08-08-prior-art-transcript-first.md`。

**這是 v1 的收尾規格。** 完成後專案進入「可用 + 可擱置」狀態：
產出真的被使用，未解的東西被明確凍結而非懸而未決。

---

## Problem Statement

使用者想把自己會看的影片批次轉成可檢索、可溯源的知識庫，餵進 Obsidian
長期複利。但目前：

1. **管線只吃得下一種影片。** 主幹是投影片切換，所以沒有投影片的素材
   （訪談、口播、動畫解說）**架構上跑不了**——不是參數不對，是沒有東西
   可以驅動分段。而使用者實際想收的影片，多數沒有投影片。
2. **分段有三分之一是錯的。** 49 個候選邊界中 17 個是「鏡頭切回講者」，
   不是內容邊界。切錯的 chunk 會把一個概念切成兩半，或把兩個概念黏在一起。
3. **溯源檢查的兩個來源不再獨立。** `provenance.py:325` 優先拿
   `transcript_corrected` 當比對基準，而那份逐字稿已被投影片文字校正過。
   投影片繞一圈從逐字稿回來，模型若讀錯，錯誤會被溯源檢查蓋章認證。
4. **沒有任何指標會說「夠好了」。** §5.2 的十項門檻全部在量「有沒有做錯」，
   沒有一項在量「做出來的東西好不好用」。所以收尾沒有終點，
   只剩一個永遠差一點的 0.95。
5. **測試跑不動。** e2e 需要下載 302MB 影片並打雲端 API，實測被 429 中斷。
   專案一旦擱置數週，回來時「現在還是好的嗎」這個問題答不出來。

---

## Solution

**把主幹從投影片切換換成逐字稿，投影片降級為可選的輔助訊號。**

```
逐字稿（手動字幕優先 → 無則 Whisper）  ═══ 主幹，一定存在
   ├─ 分段依據：語意連貫度（TextTiling + Sentence-BERT）
   └─ 溯源基準：transcript_raw（永不使用校正後版本）

投影片（可選）
   ├─ 有 → 切換點作為候選邊界（需語意佐證才採納）
   │        + S4b 術語校正（已完成）
   │        + 圖表描述
   └─ 無 → 管線自然退化，不報錯、不中止
```

分段方法對兩類素材相同，因此「有沒有投影片」不再是架構問題。

同時收掉四件擋在收尾路上的事：溯源獨立性、測試可重現性、S-1 判準的比較基準、
以及把刻意不做的東西寫成明確的凍結清單。

## User Stories

**主幹化**

1. 作為使用者，我要管線在影片沒有投影片時照常跑完，這樣我才能把訪談和口播
   類的影片也收進知識庫。
2. 作為使用者，我要分段依據是「講者講到哪裡換了話題」而不是「鏡頭切了」，
   這樣每個 chunk 才是一個完整的想法。
3. 作為使用者，我要投影片切換仍然被納入參考，這樣有投影片的影片不會因為
   改版而變差。
4. 作為使用者，我要分段在中文逐字稿上有效，包含 ASR 產生的同音錯字，
   這樣我的素材（中文、含簡繁混雜）才適用。
5. 作為使用者，我要在沒有手動字幕時自動改用 Whisper，這樣我不必挑影片。

**溯源與信任**

6. 作為使用者，我要溯源檢查的比對基準是未被校正污染的原始逐字稿，
   這樣「這段話有出處」才是真的有出處。
7. 作為使用者，我要能分辨一段內容「溯到逐字稿」和「溯到投影片」，
   這樣我在 Obsidian 引用它時知道是誰說的。
8. 作為使用者，我要一段內容如果只有靠校正才對得上，被標記出來而不是靜默通過，
   這樣我知道哪些結論依賴模型的判讀。

**驗收與終點**

9. 作為使用者，我要有一個指標告訴我「這批 chunk 好不好用」而不只是
   「有沒有做錯」，這樣我知道什麼時候可以停。
10. 作為使用者，我要每支影片各自的溯源閘門與全域統計分開呈現，
    這樣我不會再拿一個混了四種成因的數字當驗收依據。

**可重現與可擱置**

11. 作為使用者，我要在沒有網路和 API 額度的情況下跑完測試，這樣我擱置專案
    幾週後回來，能立刻知道現在還是不是好的。
12. 作為使用者，我要一份「刻意不做什麼」的清單，這樣三個月後的我
    分得出哪些是沒做完、哪些是決定不做。
13. 作為使用者，我要 S-1 用「本系列已跑過影片的彙總」當比較基準，
    而不是第 1 集的 profile，這樣換一個系列時它不會誤中止。

**跑起來**

14. 作為使用者，我要跑完機器人學課程播放清單（26 支），這樣我研究領域的
    材料真的進了知識庫。
15. 作為使用者，我要跑完兩支沒有投影片的影片，這樣我確認管線真的通用了。
16. 作為使用者，我要 `chunks.jsonl` 能落成 Obsidian `.raw/` 收件匣看得懂的
    格式，這樣我既有的 ingest 流程可以直接接手。

## Implementation Decisions

### D-A：主幹是逐字稿，投影片是輔助

`Segment` 的產生不再由 `Slide` 切換決定。S3 的職責從「對齊」變成「分段」。

**理由**：使用者實際素材多數無投影片；且視覺驅動分段有已知的結構性缺陷
（lecturer's motion，見 research §2）。

### D-B：分段用 TextTiling + Sentence-BERT，投影片切換為候選邊界

- 基礎訊號：連續段落之間的**語意連貫度下降**
- 投影片切換點**降級為候選邊界**，需同時有語意變化才採納
  （即提案 §6 的方向 2）
- 中文以 **subword n-gram** 為輔助表示——對 ASR 同音錯字有韌性
  （research §3.2；與 R18 的 bigram 觀察一致）

**模型**：本地 sentence-transformers，離線、零額度。

**這是既有的無監督標準方法，不是自創。** 不需要標註資料。

### D-C：溯源基準永遠是 `transcript_raw`

`provenance.py:325` 目前是 `seg.transcript_corrected or seg.transcript_raw`。
改為只用 `transcript_raw`。

但**不是單純換一個變數**——那會讓通過率下降（content_block 用的是校正後的
正確詞，對不上 raw 的錯字）。採用 R27 已經寫好的 `_diagnose_wrong_source`
手法：

> 若一段內容**只在 corrected 版本對得上、raw 版本對不上**，
> 它實質上溯到的是**投影片**，不是逐字稿。標為 `slide_ocr`
> 或標記 `depends_on_correction`。

**理由**：這是「校正把來源 A 的資訊寫進來源 B，再拿 A 和 B 互相驗證」的
循環。§5.4 已警告過獨立性下降，但實作比警告描述的更嚴重一級。

### D-D：無投影片時管線退化，不中止

`Slide`、`Understanding.slide_text`、`圖表描述` 全部成為可選。
無投影片的影片走：S0 → S1a → S3（語意分段）→ S4c → S5 → S6。

S1b/S1c/S4a/S4b 在無投影片時跳過，不報錯。

### D-E：S-1 的比較基準改為本系列彙總

§4.0 的中止判準目前比對 §1.3（第 1 集的 profile）。改為比對
`out/profile/{series_id}.json` 的彙總；系列第一支時才用 §1.3。

**理由**：§4.0 自己寫「這個階段只回答**這一支能不能用現有設計處理**」，
但判準實際問的是「這一支像不像第 1 集」。規格的意圖與判準不一致。
純螢幕錄影（無講者入鏡）會嚴重偏離判準 1，但那是**更好處理**的情況。

### D-F：門檻拆成兩個符號

| 符號 | 語意 | 行為 |
|---|---|---|
| `PROVENANCE_PER_VIDEO_GATE = 0.95` | §5.4 原意：單支 unverified > 5% → `needs_review`，不進 `chunks.jsonl` | **真的擋** |
| `provenance_rate_overall` | 全域實測值 | **只記錄**，不設門檻 |

**這不是調低門檻**（不違反 §5.5 #7），是修正 §5.2 把 per-video 閘門
錯寫成全域驗收指標的規格 bug。R27 已證明合計數字混了四種成因，
本來就不該當驗收指標。

### D-G：CV 跨集前濾接進 src

R26 §4 的 `cross_episode.py`：對每張代表幀計算與**其他集**代表幀的最小灰階
MAE，低於 6.0 判為包裝（片頭、片尾、佈景標語、講者學經歷）。

實測：抓到包裝 29/54，**誤殺投影片 0/26**。純本地 CV，零額度。

依使用者決定，**包裝段落直接排除**，不進知識庫。

### D-H：不使用雲端 API

全部走本地 ollama。`stages/providers.py` 的雲端支援保留但不啟用。

**代價**：溯源 0.986 → 0.838，`slide_text` CER 上升。已知且接受，
寫入 `docs/FROZEN.md`。

### D-I：R20 重測排在主幹化之後

把 R20 的全域 200 字 `initial_prompt` 改成**逐段局部 prompt**
（詞序列格式、隨段落取當下投影片），對照 DocWhisper 的做法。

**必須排在 D-B 之後**：文獻明確指出 misaligned slides **會讓結果變差**
（research §5）。分段沒修好之前，「逐段」本身就是錯的。

### D-J：新增「好不好用」的評測出口

現行十項門檻全部在量正確性，沒有一項在量可用性。納入檢索導向的評測
（Video-RAC 使用 RAGAS：Answer Relevance / Context Relevance / Faithfulness）。

⚠️ **RAGAS 對中文與本專案素材的適用性未評估。** 這張票的第一步是評估，
不是直接接上。若不適用，改用可行的替代並記錄理由。

## Testing Decisions

**什麼是好測試**：只測外部行為，不測實作細節。分段的測試應該斷言
「這兩句話在同一段」，不是「內部相似度矩陣長什麼樣」。

**e2e 拆兩層**：

| | 依賴 | 何時跑 |
|---|---|---|
| `test_e2e_offline` | 只用快取的 IR fixture | 每次，CI 可重現 |
| `test_e2e_live` | 需下載 + 本地 ollama，標 `@pytest.mark.live` | 手動 |

**要測的模組**：`stages/align.py`（分段，改動最大）、
`validation/provenance.py`（溯源基準）、`stages/dedup.py`（前濾）、
`stages/survey.py`（S-1 判準）。

**Prior art**：`tests/test_unit_align.py`、`tests/test_unit_provenance.py`、
`tests/factories.py` 的既有 fixture 慣例。黃金集格式見 `tests/golden/`
與 `GoldenAnnotation`（含 `holdout` 保留集，測試斷言保留集必須存在）。

**黃金集要擴充**：分段的 ground truth（哪裡是真的內容邊界）目前不存在。
至少需要一支影片的人工分段標註，且**必須有保留集**——R26 的教訓是
調校集上的 1.000 可能只是素材的統計巧合。

**門檻護欄照舊**：`test_every_acceptance_threshold_is_actually_enforced`
仍然生效。新增的門檻若暫時接不上，列入 `DANGLING_THRESHOLDS` 並在
`known-risks.md` 留紀錄（配套測試會檢查）。

## Out of Scope

- **Obsidian 整合**。SDD §1.2 不變。`chunks.jsonl` → `.raw/` 的轉換腳本
  屬於 vault 的 `_meta/`，不屬於本 repo。
- **Encoder-level ASR fusion**（LCB-net 類）。要改模型或微調，
  成本與本專案定位不符。
- **階層式分段（TreeSeg）**。使用者有此構想且文獻支持，但未評估。
  列為獨立探索票，不在收尾範圍。
- **公開語料（SlideSpeech / M3AV）的採用**。語種未證實，
  在確認之前不能拿來定門檻或參數。
- **多模態向量檢索（CLIP embedding）**、**跨影片 concept registry**。
  仍為 SDD §7.5 的 v2。
- **追 §5.2 的 0.95 到綠燈**。依 D-F，該數字的語意已修正。

## Further Notes

**收尾的定義**（使用者確認）：跑完一個真實 playlist，產出被實際使用；
解決不了的東西明確凍結，且不影響產品完整性。

**素材範圍**：三組全跑——機器人學課程（26 支，有投影片）、
Best Partners TV（訪談，無投影片）、大问题 Dialectic（口播，無投影片）。
中醫講經維持既有黃金集角色。

**前人工作**：`docs/research/2026-08-08-prior-art-transcript-first.md`。
其中 §4 對 R20 的修正、§3.3 對無投影片素材的結論，
是本規格兩個關鍵決策的依據。

**時間**：使用者明示無時間壓力，做好優先。但本專案會被擱置數週再回來，
因此「回來時能不能接上」是實質約束——這是 D-F、e2e 拆分、
`FROZEN.md` 三項的共同理由。
