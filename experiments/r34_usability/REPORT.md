# R34（票 12）：可用性指標——RAGAS 不用，檢索指標**有區辨力但樣本太小**

2026-08-08。票 12 的第一步是**評估**，不是直接接上。評估完了，結論在下面。

---

## 1. RAGAS：不採用

**理由不是「裝不起來」，是它的三個指標全部要 LLM 當裁判。**

| RAGAS 指標 | 怎麼算 |
|---|---|
| Answer Relevance | LLM 從答案反推問題，比對與原問題的相似度 |
| Context Relevance | LLM 從 context 抽出「相關的句子」 |
| Faithfulness | LLM 把答案拆成主張，逐條對 context 檢查 |

在這個專案裡，那會是**用本地 LLM 去評判本地 LLM 的產出**——
正是票 01 剛修掉的「用來源 A 驗證來源 A」。

而且這不是理論顧慮。R21／R26 已經量過本地模型在這批中文素材上的表現：

- 投影片分類：同一個模型、同一批圖，光改 prompt 措辭就在 **0.636–1.000** 之間跳
- `slide_text` CER：**4.9%–37.8%**，視模型而定

拿一個這種穩定度的裁判去打分，量到的會是裁判的心情。

**FROZEN F4 的同一條紀律**：拿英文語料的結論套中文素材是推廣錯誤。
RAGAS 的門檻值（Video-RAC 報 0.87／0.82／0.91）也是英文素材上的，
就算接上去也不能拿那些數字當參照。

## 2. 改用檢索指標：完全機械化，沒有裁判

把使用者會問的問題向量化，看正確的 chunk 排第幾。
它回答的是**「我找不找得到我要的東西」**。

題組：`questions.json`，18 題，每題人工標出能回答它的 chunk。
判定標準是 §3.5 的自足要求——**讀那個 chunk 就答得出來，不必看別的**。

| | R@1 | R@3 | R@5 | MRR |
|---|---|---|---|---|
| weft chunk + `bge-m3` | **0.944** | 1.000 | 1.000 | **0.963** |
| weft chunk + `MiniLM` | 0.722 | 0.889 | 0.944 | 0.812 |

單看這一組數字證明不了任何事——沒有對照組的話，它可能只是語料太小。
對照組見 §3。

## 3. 對照組：第一版寫錯了，修對之後結論翻過來

加一組**固定 200 字視窗**的 chunk——不做語意分段、不做理解、不做溯源。

### 3.1 第一版的數字是建構假象

第一版的 gold 對映是「**只要有 >0 秒重疊就算命中**」。那讓對照組在一個
**更容易的題目**上計分：

- 58 個 naive chunk 拿到 gold 資格，其中 **12 個（21%）**與真 chunk 的
  重疊不到自身時長的 25%——一個內容 75% 不相干的視窗被算成命中
- gold 集平均 2.39 個（weft 1.78），候選池只有 40 個（weft 69），
  隨機命中率高 **1.7 倍**

於是量到的差距只有 R@1 0.055，而我據此寫下「這個指標分不出 weft 與
什麼都不做的差別」——**那個結論是對照組的錯，不是指標的錯**。

> **R23 的教訓又發生一次**：對照組出錯時不會長得像「對照組錯了」，
> 會長得像「這個訊號沒那麼準」。

### 3.2 修對之後

門檻改為「naive chunk **自身時長**有 ≥50% 落在真 chunk 裡」，
並且**兩邊用同一組題**（對照組對映不到 gold 的 2 題兩邊都排除）：

| | chunk 數 | R@1 | R@3 | MRR |
|---|---|---|---|---|
| **weft** | 69 | **1.000** | 1.000 | **1.000** |
| **naive-200** | 40 | 0.812 | 0.938 | 0.875 |
| **差距** | | **+0.188** | +0.062 | **+0.125** |

R@1 的差距是 **+0.188**，第一版量到的是 +0.055——**3.4 倍**。

### 3.3 但這仍然不足以訂門檻，理由不同了

**必須揭露一個選擇效應**：被排除的 2 題是「養肝有什麼方法？」與
「肝臟除了盤點還做什麼？」，而**前者正是 weft 唯一沒排第一的題**
（rank 3）。排除的理由是對照組對映不到 gold，與 weft 的表現無關，
但兩者恰好重合——所以 weft 那個 1.000 有一部分是運氣。

全 18 題時 weft 是 **R@1 0.944 / MRR 0.963**（對照組在其中 2 題無法計分）。

因此正確的結論是：

- **這個指標有區辨力**（+0.188 R@1，不是 +0.055）
- **但 16 題太少**，而且排除規則與 weft 的失敗題重合
- **仍然不訂門檻**——理由從「指標沒用」變成「樣本太小」

## 4. 什麼樣的指標才分得出來——沒有實作，只提出

三個方向，都還沒做：

1. **自足性**：把檢索到的 chunk 單獨拿給人看，問「這段話單獨讀懂不懂、
   答不答得了那個問題」。naive 切法會在這裡失分，因為它從句子中間切開。
   **需要人工評分**，但不需要 LLM 當裁判。
2. **需要完整論證的問題**：「為什麼肝病很難治」要的是一整段推理
   （帳全錯 → 無從下手 → 只能早睡早起），naive 切法會把它切散。
   現有題組偏向事實查找，換一批題就能量到差別。
3. **擴大語料**：票 11 的 26 支課程 ≈ 800 個 chunk。干擾項多 10 倍之後
   R@1 才會有區辨空間。

## 5. 順帶量到的一個實質品質問題（**第一版的數字也錯了**）

讀 chunk 時發現產出裡混著簡體字與英文。

| | |
|---|---|
| 真正只出現簡體寫法的 chunk | **7/69 = 10.1%** |
| 含英文單字（≥3 字母）的 chunk | 6/69 = 8.7% |

例子：`小 intestine`、`幽门杆菌`、`恶搞`、`妈妈`、`小肠`、`仓库`。

**第一版寫的是 27.5%，那是錯的。** 我用 `s2tw` 逐字比對、把任何被改寫的
字都算成簡體，而它會標記**異體字**：`吃`（×10）、`回`（×10）、`了`（×4）、
`游`（×4）、`制`、`秘`、`群`——這些字**手動字幕裡也有**，是原文就有的
繁體／異體寫法，不是模型生成的。扣掉之後才是 7/69。

### ⚠️ 不要照第一版寫的「在後處理轉繁」去做

**`游` 是講者的姓**（游朱義）。對 S4c 的產出跑 `s2t` 會把它改成 `遊朱義`，
還會把 `吃`→`喫`、`台`→`臺`——**正好製造這一節說要避免的連結錯亂**，
而且是在本來就正確的文字上。D24 已經為同一件事踩過坑
（`s2twp` 把 `局部`→`區域性`）。

成因仍然成立：D24 只把 ASR 輸出轉繁，S4c 生成的內容沒有任何字集正規化。
要修只能針對**確認是簡體的那些字**做白名單式替換，或在 prompt 上要求
（而 D31 已經量過 14B 模型對長 prompt 的反應）。列為後續票，見
known-risks R24。

## 6. 結論與門檻

**不訂門檻**，但理由與第一版寫的不同。

第一版寫的是「指標沒有區辨力」——那是我的對照組寫錯造成的（§3.1）。
修對之後 R@1 差距是 +0.188，**指標是有區辨力的**。

不訂門檻的真正理由：

1. **16 題太少**，而且排除規則恰好排掉了 weft 唯一失敗的題（§3.3）
2. **語料只有 69 個 chunk、兩支影片**。票 11 的 26 支 ≈ 800 個 chunk，
   干擾項多 10 倍之後這個差距會放大還是縮小，沒有資料
3. 票裡自己寫的紀律：「不憑感覺訂門檻——首版只記錄」

`docs/FROZEN.md` F2 說 0.95 的恢復觸發條件是「當有了產出好不好用的評測」。
**現在有一個雛形了**，但它還不夠穩到能拿來訂另一個門檻。
差別在於：第一版的結論是「這條路走不通」，修正後的結論是
**「這條路走得通，但要更多資料」**。

## 7. 這一輪的方法論教訓

**對照組出錯時會偽裝成「訊號不準」**（R23 已經記過一次，這是第二次）。

第一版的 `remap_gold` 用「有重疊就算」，看起來是合理的寬鬆對映，
實際上把對照組的題目變簡單了。而症狀是「weft 只比 naive 好 0.055」——
那個數字看起來就像「指標不夠敏感」，完全不像「對照組算錯了」。

唯一抓到它的方式是**去看對照組的 gold 集到底長什麼樣**：
58 個 naive chunk 拿到資格、其中 21% 的重疊不到自身時長的四分之一。
平均分永遠不會告訴你這件事。
