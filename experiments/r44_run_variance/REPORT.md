# R44：模型輸出的跑次變異有 2.3 倍——今天有一批結論因此站不住

2026-08-09。**這份報告推翻我自己在 R43 下的結論，並標出今天其他
哪些數字是不可靠的。**

起因：R43 判定 S4c prompt v8 是淨損失（調校集 −50%）。
為了補上 R43 §8 自己標的限制（「v7 那一邊是 n=1」），
把 v7 也清快取重跑了幾次。

---

## 0. 結論先講

| | |
|---|---|
| **`temperature=0.2`、無 seed** | 模型不是確定性的，而**沒有人量過它的變異** |
| **同設定的總字數差 2.3 倍** | `cxrqHABhWOU` v7：1386 / 818 / 600 |
| **R43 的結論是錯的** | v8 的三個值**全部落在 v7 的範圍內** |

## 1. 量到的分佈

`cxrqHABhWOU`，10 個 segment，同一組 `input_fingerprint`，
清 `07_understanding` 快取後重跑：

| prompt | n | 樣本（總字數） | 平均 | 標準差 | CV | 全距 |
|---|---|---|---|---|---|---|
| **v7** | 5 | 1386 / 818 / 600 / 722 / 1041 | 913 | 310 | **0.34** | **2.31×** |
| v8 | 3 | 696 / 684 / 738 | 706 | 28 | 0.04 | 1.08× |

block 數：v7 12 / 14 / 11 / 12 / 17；v8 11 / 13 / 15。

**v7 單一樣本的粗略 95% 區間是 294–1533。** 也就是說：拿一次 v7 的結果
去跟任何東西比，等於在一個橫跨五倍的區間裡抽一個點。

`2FjApOVIbUs`（16 個 segment）只有兩個 v7 樣本：**1848 / 3062**（1.66×）。

## 2. R43 錯在哪

R43 的比較是：

```
v7 = {1386}          ← n=1
v8 = {696, 684, 738} ← n=3
結論：v8 讓產出量腰斬
```

補上 v7 的樣本之後：

```
v7 = {1386, 818, 600, 722, 1041}   平均 913、CV 0.34
v8 = {696, 684, 738}               平均 706、CV 0.04
```

**v8 的三個值全部落在 v7 的範圍內。**

平均差 −23%，但 v7 的標準差是 310——這個差距在雜訊裡。
**沒有證據說 v8 降低了產出量**，更沒有 R43 寫的「腰斬」。

R43 §4 標題寫「為什麼敢說不是雜訊」，理由是「量了 v8 的變異是 ±4%」——
**那只證明 v8 穩定，沒有證明 v7 穩定**。而 v7 才是被拿來當基準的那個。

> 這是今天第四次同一類錯誤：R23（對照組出錯）、R37（對照組缺席）、
> R40 §2.1（對照組落在較容易的題目上），現在是**對照組只有一個樣本**。

## 3. 一個可能是真的、但需要更多樣本的觀察

**v7 的 CV 是 0.34，v8 是 0.04——差了將近十倍。**

如果這成立，v8 的價值不是「寫更多」而是「**寫得比較穩定**」——
那對一個要長期累積的知識庫其實有意義。

**但 n=3 對 n=3 支撐不了這個結論**，而且變異的變異更難估。
沒有據此把 v8 改回來。

## 4. 今天哪些結論還站得住

### 4.1 不受影響（確定性計算，不呼叫模型）

- **R37**：容忍窗覆蓋率、等距對照組
- **R40**：α 掃描、WindowDiff、固定長度對照、段長分佈
- **R41**：DP 分段與混合法
- 這些全部是在**已快取的逐字稿與黃金集**上算的。
  重跑一百次結果完全相同。

**所以「原設定在三支上輸給一刀不切」這個核心發現不受影響。**

### 4.2 受影響，需要重新認定

| 原本的說法 | 現況 |
|---|---|
| 「α 改動讓 `2FjApOVIbUs` 內容掉 47%」 | 3472（n=1）對 1848（n=1）。而 v7 在該支的兩個樣本是 1848／3062 → **幅度不可信** |
| 「v8 是淨損失」 | **已推翻**（本報告 §2）|
| 溯源通過率 0.958 → 1.000 等 | 全部是單次。**趨勢方向可能對，幅度不可信** |
| R39 的拼音增益 +0.004 | 跨 447 個 block 的平均，比單一數字穩，但底層 IR 仍是單次樣本 |
| R42 的符號告警率 25.0% vs 1.6% | 同上。**兩組來自同一次抽樣**，所以組間比較比絕對值可靠 |

### 4.3 結構性的觀察仍然成立

**「S4c 每段產出的 block 數與段落長短無關」**——
`cxrqHABhWOU` 的段落在 α 改動後長度加倍（19 段 → 10 段），
而每段 block 數是 1.26 → {1.2, 1.4, 1.1}，**沒有跟著變**。

這是跨設定、跨多次抽樣都成立的形狀，不是單次數字。
**所以 R35 記的那個機制是對的，只是「掉了 47%」這個幅度不可信。**

## 5. 處置

- **R43 已更正**，結論改為「無證據顯示 v8 降低產出量」。
  v8 仍**不採用**——它沒有解決要解的問題（產出量沒上升），
  而 `2FjApOVIbUs`／`UiKi5-Arce4` 的樣本也不足以支撐「它更穩定」。
- **`content_yield()` 與 `MIN_CHARS_PER_1K_SOURCE` 保留。**
  它們的價值反而更高了——**沒有它們，這個 2.3 倍的變異到現在都不會被發現。**
- 下限 100 的寬鬆度事後看是對的：實測最低樣本是 600 字 / 2983 字源
  = **201**，若當初訂在 300 就會誤殺。

## 6. 給下一個人的規則

> **任何依賴 S4c 輸出的比較，兩邊都要至少 3 個樣本。**
> 清 `work/<vid>/07_understanding` 就會重新呼叫模型。
> 一次 10 段的影片約 10 分鐘。

而且：

- **不要拿 block 數當產出量指標**——它的變異（±18%）比字數（v8 ±4%）大。
  但注意 v7 的字數變異是 ±40%，所以**兩個都不穩**，只是不穩的程度不同。
- **不要只跑一次就寫進報告**，即使數字看起來很乾淨。

## 7. 限制

- 只量了 `cxrqHABhWOU`（10 段、2983 字逐字稿）的完整分佈。
  **長影片的變異可能不同**——段數多也許會平均掉一部分。
- `2FjApOVIbUs` 只有 2 個 v7 樣本，`UiKi5-Arce4` 只有 1 個。
- 沒有查變異的來源。`temperature=0.2` 是預設值，
  **沒有人試過 0.0**——那可能讓整件事消失，但也可能讓輸出變差。
  **未評估。**
