# R42：具名實體檢查在 STEM 素材上是空轉的

2026-08-09。起因是 Q3 的稽核：查 `slide_ocr` 為什麼 0% 失敗時，
順手驗了一下抽取器。

```
extract_named_entities("四乘四矩陣用於表示坐標系B到坐標系A的完整轉換")
→ frozenset()
```

**一個實體都抽不到。** 它抓的是書名、年代、中文數字——那是為中醫講經
設計的。所以在機器人學素材上，具名實體檢查等於沒有在跑。

而 R39 §3.1 手讀時判定為**真編造**的那一筆，正是這一類。

---

## 0. 結論先講

| | |
|---|---|
| **區辨力很強** | 未通過組告警 **25.0%**、通過組 **1.6%**（15.6 倍）|
| **但當閘門加不了值** | 被抓到的 block **本來就已經未通過** |
| **當閘門還會誤殺** | 多抓的 1.6% 是正規化（`Rₓ`、`Rcz(θ)`）不是編造 |
| **所以定位成診斷** | 把 R39 手讀才分得出的成因自動化 |
| **實際效果** | `UiKi5` 原本 8 個不透明的「溯不到」，**3 個有了具體解釋** |

---

## 1. Q3 的前提是錯的，一併更正

原本的說法是「`slide_ocr` 有 17% 的內容免試通過，通過率的分母裡混著
一批沒被檢查的」。拆開量之後不是這樣：

| 型別 | n | 相似度中位 | 門檻 | 低於門檻 | 有具名實體 | 實體缺漏 |
|---|---|---|---|---|---|---|
| 經文原文 | 19 | **1.000** | 0.60 | 0 | 12 | **0** |
| 圖表描述 | 11 | 0.109 | **0.00** | 0 | 10 | **0** |
| 白話解說 | 4 | 0.197 | 0.10 | 0 | 2 | **0** |

`slide_ocr` 之所以 0% 失敗，是因為**它們真的溯得到**——經文原文的
相似度中位是 1.000（就是投影片上的原文）。**不是免試，是考了滿分。**

真正沒有閘門的只有「圖表描述」那 11 個（門檻 0.0），
而那是 R12 實測逼出來的已知取捨（跨語言時忠實翻譯的字面相似度本身
就是 0.000），已記在 known-risks R12。

## 2. 符號抽取

| 樣式 | 例 |
|---|---|
| 函式形 | `Rz(φ)`、`Euler(φ, θ, ψ)` |
| N×N | `4x4`、`3×3` |
| 下標 | `R₁₁`、`n₃`、`nₓ` |
| 字母+數字 | `R11`、`T_2` |

**刻意不抓單獨的大寫字母**——「A 乘 B」裡的 A、B 太常見，
抓了會把每個 block 都告警。

### 2.1 第一版的 bug：`4x4` 被切出一個假的 `x4`

樣式若各自獨立比對，`[A-Za-z]_?\d{1,3}` 會在 `4x4` 內部匹配到 `x4`。
**通過組的誤報有一半來自它。**

改成**不重疊抽取、長樣式優先**之後：

| | 第一版 | 修正後 |
|---|---|---|
| 未通過組告警率 | 20.0% | **25.0%** |
| 通過組告警率 | 2.6% | **1.6%** |
| 區辨倍數 | 7.7× | **15.6×** |

### 2.2 變體正規化是必要的

模型會把口說的「四乘四」寫成 `4x4`、「R 一一」寫成 `R₁₁`——
**那是書面化不是幻覺**（R36 記過）。沒有變體比對，這些全會變成誤報。

`4x4` 的變體涵蓋 `4×4`、`4乘4`、`4乘以4`、`四乘四`、`四x四`、`四乘以四`。

## 3. 結果

| 素材 | 組別 | n | 有符號 | 告警 | 告警率 |
|---|---|---|---|---|---|
| STEM | 未通過 | 20 | 5 | 5 | **25.0%** |
| STEM | 通過 | 191 | 35 | 3 | **1.6%** |
| 其他 | 未通過 | 10 | 0 | 0 | 0.0% |
| 其他 | 通過 | 166 | 4 | 0 | 0.0% |

中醫講經與純口播那批**一筆都沒告警**——符合預期（沒有數學符號），
也證明它不會平白製造噪音。

### 3.1 抓到的（未通過組）

```
UiKi5#015#b03  ['R₁₁', 'R₁₂']   旋轉變換不具有交換性，即 R₁₁(a) • R₁₂(β) ≠ …
               逐字稿：旋轉本身是不可以交換　旋轉矩陣是個3乘3的　我對某個軸轉幾度
```

**這就是 R39 §3.1 手讀判定為真編造的那一筆。**

```
UiKi5#008#b01  ['4x4']                     這些轉換關係可以用4x4矩陣來表示
UiKi5#013#b01  ['Translation(P)', 'Translation(Q)', '4x4']
xBfy#047#b00   ['n₂', 'n₃', 'nₓ']          φ=tan⁻¹(n₃/nₓ)…
```

### 3.2 誤報候選（通過組，3 筆）

```
UiKi5#019#b00  ['Rₓ']      「對於X軸的旋轉」→ 寫成 Rₓ
UiKi5#029#b02  ['Rcz(θ)']
xBfy#019#b00   ['3x3']     逐字稿那一段是「有個數值方法上的考量好OK好…」
```

前兩筆是**標準的書面化**，講者說「對 X 軸旋轉」而模型寫 `Rₓ`——
不算編造。第三筆的逐字稿品質很差，難以判斷。

## 4. 為什麼是診斷不是閘門

被它抓到的 5 筆**本來就已經未通過**了，所以當成新閘門**加不了值**。
而它多抓的 3 筆通過組看起來是正規化，當閘門會誤殺。

它真正的價值是**把「為什麼失敗」自動化**：原本那些 block 的失敗原因
只寫「與來源相似度 0.039」，R39 是靠人逐段讀才分出三種成因。

實際效果（回填後）：

| 影片 | block | 通過率 | 歸屬錯 | 靠校正 | 溯不到 | **含編造符號** |
|---|---|---|---|---|---|---|
| `UiKi5-Arce4` | 67 | 0.866 | 1 | 0 | 8 | **3** |
| `xBfyWwYylSA` | 89 | 0.899 | 5 | 0 | 4 | **2** |
| `cxrqHABhWOU` | 12 | 1.000 | 0 | 0 | 0 | 0 |

`UiKi5` 原本 8 個不透明的「溯不到」，**3 個有了具體解釋**。

> 這一欄與前三類**不互斥**——它是「為什麼溯不到」的側寫，不是另一個桶子。
> 混進 `unresolved` 的分母會讓那一欄失去意義。

## 5. 限制

- **兩支 STEM 影片、20 個未通過 block。** 25.0% 這個數字是 5/20。
- 誤報判定（§3.2 那三筆）**是我自己讀的**，沒有第二個人複核。
- 樣式是**手寫的正規表示式**，只涵蓋看得到的形狀。希臘字母單獨出現
  （`θ`、`φ`）沒有抓——它們太常見，抓了誤報會爆掉。**沒有量過那個假設。**
- 沒有處理 LaTeX（`\theta`）或全形符號。目前素材裡沒出現。
