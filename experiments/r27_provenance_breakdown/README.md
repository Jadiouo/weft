# R27：把溯源通過率 0.838 拆開——一半不是內容問題

2026-08-08。四支影片、167 個 content block、通過 140（**0.838**，§5.2 門檻 0.95）。

**這個數字混了四件不同的事，修法完全不同。**

---

## 1. 拆解結果

| 成因 | 筆數 | 這是什麼 |
|---|---|---|
| **歸屬錯**：內容溯得到**同一段的另一個來源** | **15** | 抄自投影片卻標成 transcript（或反之）。不是幻覺，是 metadata 標錯 |
| 兩個來源都對不上 | 10 | **真正要判「內容有沒有問題」的只有這些** |
| 來源投影片其實不是投影片 | 2 | 分類誤報的下游後果（R26 的紅燈） |
| ~~`ref` 格式錯~~ | ~~3~~ | 已修，見 §3 |

**未通過的 27 筆裡，有 17 筆的病根不在內容品質。**
歸屬錯與分類誤報都修好的話，通過率會是 **157/167 = 0.940**——
仍未達 0.95，但那時剩下的 10 筆才是誠實的「內容或檢查適用性」問題。

## 2. 歸屬錯是怎麼看出來的

一段有**兩個**來源：S4a 讀出的投影片文字，與這一段的逐字稿。
未通過時，拿另一個來源再算一次 containment：

```
zIgl/018 白話解說   對逐字稿 0.000   對投影片 0.560
zIgl/030 白話解說   對逐字稿 0.088   對投影片 0.593
C_CF/024 口頭延伸   對逐字稿 0.000   對投影片 0.536
2FjA/027 白話解說   對逐字稿 0.038   對投影片 0.513
```

**差距不是邊緣值**——標錯的那個是 0.00–0.09，對的那個是 0.51–0.59。

已做進 `validation/provenance.py` 的 `_diagnose_wrong_source`，
結果記在 `BlockVerdict.wrong_source`。

**刻意不自動改判為通過。** §3.5 要求 chunk 自足，
「投影片寫了 X」與「講者說了 X」在下游是兩件事，metadata 帶錯就是帶錯。
這一道只是把「歸屬錯」與「編造」分開，讓兩者各自去修。

## 3. 順手修掉的實作缺陷：`ref` 不該由模型提供

3 筆未通過的原因是模型把 `slide_015` 寫成 `015`：查不到投影片 →
來源字串為空 → `source_ratio` 0% → 未通過。
而失敗訊息顯示「**來源長度僅 block 的 0%，撐不起這段內容**」——
看起來像內容太長，其實是查無此人。**內容本身是忠實的。**

修法不是模糊比對（§5.3 不變量 10 禁止），而是**改用權威值**：
一段只會拿到一張投影片的文字（`slide_context` 只掛那一張），
所以 `slide_ocr` 的合法來源只有一個，`transcript` 的區間就是這一段的起訖。
模型寫的那個欄位從頭到尾都是多餘的。

正規化放在 `_apply_to_segment`，**快取命中與新呼叫都會走**——
只放在解析那條路上的話，續跑會沿用磁碟上的舊值（D22 同一個坑）。

## 4. 真正對不上任何來源的 10 筆

| | 未通過原因 |
|---|---|
| 5 筆 | containment 低於型別門檻（0.010–0.121） |
| 5 筆 | 具名實體未出現於來源 |

具名實體那 5 筆值得逐筆看：

```
zIgl/016  ['太上老君內觀經']   ← 書名出現在投影片，不在該段逐字稿
C_CF/019  ['素問']            ← 同上
2FjA/028  ['5','6','7']       ← 胸椎節數，講者口說「T5 T6」，逐字稿寫法不同
2FjA/034  ['5','6']           ← 同上
2FjA/019  ['兩']              ← **抽取器誤判**：「兩大原因」的「兩」被當成數字
```

前四筆是**同一個病**——具名實體檢查只看宣告的那個來源，
跟歸屬錯是同一件事的另一面。最後一筆是抽取器本身的誤報。

**所以 10 筆裡真正可能是內容問題的，不到 5 筆。**

## 5. 這對 §5.2 的門檻意味著什麼

R12 已經量過：containment 對 `白話解說`（1.14x）、`口頭延伸`（0.54x）、
`圖表描述`（0.00x）沒有鑑別力，門檻只擋退化情形。
**現在知道通過率低的主因也不是那件事**——是歸屬與分類。

順序因此清楚了：

1. **先修歸屬**（S4c 的 prompt）——15 筆，最大宗，且與內容品質無關
2. **分類紅燈**（R26）——2 筆在這四支上，但代價高：把講者鏡頭判成投影片，
   攝影棚佈景的書法就成了 §5.4 的合法來源
3. **具名實體抽取器的誤報**（「兩大原因」）——一行 regex
4. 剩下的才是「內容品質 vs 檢查適用性」，而那時樣本只剩個位數，
   **要先擴大樣本才有意義**

## 6. 限制

- 四支影片、167 個 block。第 4 步的樣本已經小到不能下結論。
- `wrong_source` 的判定用 `sim ≥ 型別門檻 且 > 原分數的 2 倍`，
  **未經校準**——目前觀察到的差距是 0.00–0.09 對 0.51–0.59，
  中間沒有樣本，所以任何倍數都一樣。累積後再定。
- 這四支的 S4a 輸出是 prompt v5 的結果；R26 記過 v5 只有 0.900，
  所以「分類誤報」那一類的筆數會隨分類改善而變動。
