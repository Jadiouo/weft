# R14：S4 的圖片↔區段錯位（v0.3 首跑）

發現時機：準備量測「本地 VLM 能否取代 Flash Lite」時，需要先建 `is_slide`
的標準答案。人工逐張判讀 49 張代表畫面後，與首跑輸出一比就發現對不上。

素材：`zIglvjoU9vo` 首跑輸出（2026-08-04）
標準答案：`labels_is_slide.json`，我逐張看圖判的，判準與 SYSTEM_PROMPT 一致

---

## 結論（先講）

**49 個區段中 15 個（30.6%）拿到了隔壁那張圖的分析結果。**

原因不是模型分類能力不足，是 `call_gemini` 把一批 3 段的**文字全部放前面、
三張圖裸接在後面**，只靠一句「圖見附件，依序對應」讓模型自己配對。

修法：**每張圖緊接在它自己的區段標頭之後**（`build_parts`），
並且缺圖時明講而不是靜靜跳過——靜靜跳過會讓後面的圖遞補上來，整批位移。

**影響範圍很廣**：`slide_text` 是 §5.4 溯源檢查的比對基準。基準本身錯置，
等於整條溯源鏈在 30% 的區段上驗錯了對象。

---

## 1. 為什麼判定是綁定問題而不是模型能力問題

若模型只是分不清「投影片 vs 攝影棚鏡頭」，錯誤應該與批次邊界無關、隨機散布。
實測不是這樣：

```
b3   seg_009–011  真值 片——  →  預測 片片—
b4   seg_012–014  真值 片—片  →  預測 片片—   ← 個數相同，只是位置換了
b5   seg_015–017  真值 —片—  →  預測 ——片   ← 個數相同，只是位置換了
b6   seg_018–020  真值 片—片  →  預測 ——片
b8   seg_024–026  真值 片—片  →  預測 —片—
b11  seg_033–035  真值 片—片  →  預測 —片片   ← 個數相同，只是位置換了
b12  seg_036–038  真值 —片片  →  預測 片—片   ← 個數相同，只是位置換了
b15  seg_045–047  真值 —片—  →  預測 ——片   ← 個數相同，只是位置換了
```

出錯的 8 個批次中 **5 個是純粹的批次內重排**——投影片的**個數完全正確**，
只是配到了錯的區段。**沒有任何錯誤跨越批次邊界。**

決定性的證據是成對出現的：

| 區段 | 它拿到的圖 | 模型的回答 |
|---|---|---|
| seg_013 | slide_014（**講者鏡頭**） | 193 字的《太上老君內觀經》全文 |
| seg_014 | slide_015（**內觀經投影片**） | 「畫面為講者鏡頭，非投影片內容。」 |

**兩段的答案剛好互換。** 同樣的成對錯位在 seg_017/018、seg_025/026、
seg_033/034、seg_036/037 各出現一次。

模型不可能對著一張講者鏡頭「幻覺」出 193 字一字不差的經文——那些字
確實在**同一批的另一張圖**上。

## 2. 錯誤的兩個方向

**方向 A：對純攝影棚鏡頭吐出投影片逐字內容**（5 筆）

```
seg_013（圖 slide_014 是講者鏡頭）→ 193 字「太上老君內觀經 天地媾精…」
seg_017（圖 slide_018 是講者鏡頭）→ 190 字，同上
seg_025（圖 slide_026 是講者鏡頭）→ 192 字，同上
seg_034（圖 slide_035 是講者鏡頭）→  87 字「第一週 第二週…《一月為胞》」
seg_036（圖 slide_037 是講者鏡頭）→  87 字，同上
```

這一類最危險：它產生了**看起來完全合理、內容也真實存在**的 `slide_text`，
只是掛在錯的時間點上。任何自動檢查都抓不到——文字是真的，來源也是真的，
錯的是對應關係。

**方向 B：對真投影片回「不是投影片」**（8 筆）

```
seg_014（slide_015 內觀經）→「畫面為講者鏡頭，非投影片內容。」
seg_016（slide_017 內觀經）→「畫面為講者鏡頭，背景文字為佈景裝飾，非教學投影片。」
seg_033（slide_034 胚胎四周）→「畫面為講者鏡頭，非教學投影片。」
…
```

這一類的後果是**整段投影片內容遺失**，`content_blocks` 只能用逐字稿。

## 3. 對既有結論的影響

| 既有工作 | 是否受影響 |
|---|---|
| R12 的對照組結論（各型別的分離度） | **不受影響**——對照組是手寫的，來源文字直接取自 slide 與逐字稿本身 |
| R12 報告中「真實資料溯源未通過 43% → 3%」 | **受影響**——那是在錯置的 `slide_text` 上量的，數字要重測 |
| R13 的 9 筆校正 | **部分受影響**——`意地論→瑜伽師地論`（seg_013）所在的批次有錯位。但 R13 的判準與門檻是在手寫對照組上校準的，結論不變 |
| R8 的疊加量測 | 不受影響——完全不經過 S4 |

**R12 的真實資料數字必須在修好後重跑。** 對照組的校準結論站得住，
但「修完之後未通過率是多少」這件事是在壞掉的基準上量的。

## 4. 修法

`build_parts` 回傳 `[(文字, 圖的 slide_id 或 None), ...]`，
`call_gemini` 照這個順序交錯疊 parts：

```
文字：## segment vid#013 … **下面緊接的那一張圖**就是這一段的代表畫面
圖：  slide_014.png
文字：## segment vid#014 … **下面緊接的那一張圖**就是…
圖：  slide_015.png
…
文字：（總指示）每一段只能依據緊接在它標頭後面的那張圖作答
```

另外兩點：

- **缺圖時不得靜靜跳過。** 原本是 `if path.exists(): contents.append(...)`，
  缺一張就會讓後面的圖全部遞補上來。改成補一句文字說明並記 warning。
- 措辭從「圖見附件，依序對應」改成「下面緊接的那一張圖」。
  前者要求模型自己做全域配對，後者是局部的、位置就在旁邊。

回歸測試在 `tests/test_unit_prompt_binding.py`，
釘住「每張圖綁在自己的區段上」與「缺圖不位移」。
