# R46：確定性是 session 範圍的——貪婪解碼解不了跨執行的變異

2026-08-13。接 R45 §5 留下的「沒有試 `top_k=1`，那可能才是真正的
貪婪解碼開關」。

**試了。它在單一 session 內有效，跨 process 無效。** 而 pipeline 的
每次執行都是獨立 process，所以**這條路走不通**。

---

## 0. 結論先講

| | |
|---|---|
| **`temperature=0` 不足** | 短 prompt 下夠，**真實規模下不夠**（695 vs 1043）|
| **`temperature=0 + top_k=1` 在單一 process 內確定** | 連呼叫 4 次，4/4 同一雜湊 |
| **跨 process 仍然變** | 695／808／863／1043，**同一設定、同一輸入** |
| **seed 完全沒有作用** | 連 `curl` 直接打都沒有 |
| **產出量還更低** | 184.7／千字，**低於 `temperature=0.2` 五個樣本的最低值（201）** |
| **不採用，設定已退回** | 但 `seed`／`top_k` 欄位保留 |

---

## 1. 一層一層縮小範圍

每一層排除一個候選。**每次都用內容雜湊比對，不只看字數**——
字數相同不代表內容相同。

| 測試 | 結果 |
|---|---|
| pipeline + 固定 seed，跑 3 次 | ✗ 1482／702／736 |
| **`curl` 直接打 + seed**（繞過我們的程式）| ✗ 仍變 → **不是我們的 bug** |
| `curl` + `temperature=0`（短 prompt）| ✓ 3/3 相同 |
| `curl` + `top_k=1`（短 prompt）| ✓ 3/3 相同，**與上一列同一個雜湊** |
| `curl` + `format` schema + `temperature=0` | ✓ 3/3 相同 |
| **真實 prompt 長度 + `temperature=0`** | ✗ **變**（695 vs 1043）|
| **真實條件 + `temperature=0 + top_k=1`** | ✓ 3/3 相同 |
| 同上再加 seed | ✓ 相同（貪婪不抽樣，seed 本來就無關）|

### 1.1 `temperature=0` 理論上該等於貪婪，實務上不是

短 prompt 下 `temperature=0` 與 `top_k=1` 給出**完全一樣的雜湊**，
所以在那個規模下兩者等價。但真實 prompt 長度下 `temperature=0` 就不夠了。

**沒有再往下追為什麼**——那要進 llama.cpp，而結論不因原因改變。

## 2. 但確定性只在單一 session 內成立

| 情境 | 結果 |
|---|---|
| **同一個 Python process 內連呼叫 4 次** | **4/4 相同**（雜湊 `2d10dadb913d`）|
| **每次獨立 process**（同設定、同輸入）| 695／808／863／1043，**全不同** |
| 完整 pipeline 跑兩次（貪婪）| 737 字／551 字，不同雜湊 |

`ollama stop` 卸載模型再跑也在這個範圍內——冷啟與暖機都會落在
那組值裡面，沒有「冷啟一種、暖機另一種」的規律。

**機制沒有查清楚。** 可能與 ollama 的 slot／prompt cache 狀態有關，
但我沒有證據，**不寫成結論**。

### 2.1 對我們的意義

pipeline 的每次執行都是獨立 process（`weft understand` 一次一個）。
所以**貪婪解碼不會讓「跑兩次比較」變得可重現**——
而那正是要解決的問題。

> **R44 §6 的規則不變**：任何依賴 S4c 輸出的比較，兩邊各至少 3 個樣本。

### 2.2 一個可用的副產品

**同一個 process 內是確定的**，所以要做 A/B 比較時，
把 A 和 B 放進**同一個量測腳本**跑，比分別跑兩次可靠得多。

`experiments/r41_dp_segmentation/` 那類（在已快取資料上做確定性計算）
本來就沒這個問題；有問題的是要重新呼叫模型的比較。
**這個技巧沒有實際用過，只是從觀察推出來的。**

## 3. 代價：產出量更低

完整跑 `cxrqHABhWOU`（貪婪，兩次）：

```
run1: 13 block、737 字
run2: 11 block、551 字     每千字產出 184.7、通過率 1.000
```

對照 `temperature=0.2` 的五個樣本：600／722／818／1041／1386
（每千字 201–465）。

**551 低於那五個樣本的最低值。** n=2 且兩次還不一樣，
所以不能說「貪婪一定比較少」——但**沒有任何跡象顯示它比較好**，
而它的唯一賣點（確定性）已經被 §2 推翻。

## 4. 處置

- **設定退回**：`temperature=0.2`，`seed`／`top_k` 不設（用 ollama 預設）。
- **`seed` 與 `top_k` 兩個欄位保留**，連同它們在取樣指紋裡的位置。
  它們現在是可設定、被記錄、改了會正確重跑的。
- **`sampling_fingerprint` 保留**——這次加兩個參數只改了一個地方，
  而反射測試第一次跑就抓到三個沒分類的欄位。那個機制證明有用。

## 5. 限制

- **只在 `qwen2.5:14b` + ollama 0.32.6 + RTX 5070 Ti 上量過。**
- §2 的機制沒有查清楚。
- 跨 process 的四個值（695／808／863／1043）**看起來像從一個小集合裡抽**，
  但 n=4 說不上是不是真的有限集合。沒有多量。
- §2.2 的「同 process 做 A/B」**沒有實際用過**。
