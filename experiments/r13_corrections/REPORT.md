# R13 校準：術語校正的授權邊界

素材：`zIglvjoU9vo` 首跑輸出的全部 9 筆校正（2026-08-04）+ 手寫對照組
方法：比照 D1／R12——建「授權 vs 未授權」對照組，量各候選規則的分離度
判準：比照 D1，**分離倍數 <2x 即判該規則不可用**，不調參數硬拉

---

## 結論（先講）

**兩件事，第二件比第一件嚴重。**

1. 模型的校正超出授權：9 筆中 4 筆不是聽寫校正（precision 0.56，§5.2 要求 ≥0.90）。
2. **prompt 寫的授權條件本身是錯的。** 它要求「正確寫法出現在這張投影片上」，
   但實測 9 筆中**只有 1 筆**滿足這條——而那 1 筆恰好是最危險的插入型違規。

第 2 點意味著模型若真的遵守 prompt，功能會歸零；它做出的每一筆有價值的校正
都違反了那條規範。**規範與任務不相交，錯的是規範。**

處置：改寫 prompt 的授權定義（改成「發音沒變、只是字寫錯」）並補負面示例，
加上程式端的三道兜底。真實 9 筆的 precision 從 **0.56 → 1.00**，誤殺 0/15。

**仍有缺口**：事實修正（`唐朝`→`宋朝`）程式端擋不到，量測證明做不到，不是還沒做。

---

## 1. 「正確寫法出現在投影片上」這條規則是反的

逐條檢查首跑的 9 筆，`to` 是否真的出現在該段的 `slide_text` 中（去空白後比對）：

| 區段 | is_slide | from → to | `to` 在投影片上 |
|---|---|---|---|
| seg_011 | ✗ | 憍梵钵提 → 憍梵波提 | ✗ |
| seg_011 | ✗ | 沒sense → 沒Sense | ✗ |
| seg_013 | ✓ | 意地論 → 瑜伽師地論 | ✗ |
| seg_021 | ✗ | 啟示經 → 創世記 | ✗ |
| seg_030 | ✓ | 陽神為三魂 → 陽神為三魂，動而生也 | **✓** |
| seg_034 | ✓ | 學古學的 → 學古文學的 | ✗ |
| seg_034 | ✓ | 投胎轉世 → 十個月懷胎 | ✗ |
| seg_045 | ✗ | 家家當 → 家當 | ✗ |
| seg_045 | ✗ | 未 → 未來 | ✗ |

**1/9。而那唯一的 1 筆是插入型違規。**

另外 5/9 來自 `is_slide=False` 的區段——**根本沒有投影片可對照**，
這條規範在那些段落上連判斷都無法進行。

若把「`to` 必須出現在投影片上」實作成程式規則：
擋掉 8/9，其中 4 筆是**合規**的校正，卻**放行**唯一真正危險的那筆。
**這條規則的鑑別力是負的。**

原因不難理解：ASR 的同音錯字（`憍梵钵提`、`家家當`）出現在講者的口述中，
不是投影片上。真正需要校正的地方，恰恰是投影片沒有涵蓋的地方。

## 2. 對照組

授權 15 筆、未授權 16 筆，其中 9 筆是模型的實際輸出（未經修改）。
判準寫在 `contrast_set.py` 每一筆的 `why` 欄。

**授權**＝`from` 是 ASR 造成的音近錯字／疊字／截斷，`to` 與 `from` 指同一個詞。
**未授權**＝改變指涉對象、增加原文沒有的內容、或根本不是術語問題。

違規分五類，各 2–4 筆：插入、事實修正、語意改寫、格式化、潤稿。

## 3. 沒有任何單一規則可用

| 規則 | 授權 (min/中位/max) | 未授權 (min/中位/max) | 分離 |
|---|---|---|---|
| 拼音相似度 | 0.400 / 0.750 / 1.000 | 0.000 / 0.429 / 1.000 | **0.40x** |
| 字數增量（負） | -2 / 0 / +1 | -6 / 0 / +6 | **-0.33x** |
| 插入新增字數（負） | -1 / 0 / 0 | -6 / 0 / 0 | **0.00x** |

全部遠低於 2x。這是**預期內**的：違規有五種不同的失效模式，
不可能靠單一純量分開。有意義的是**逐類別**看：

| 類別 | 授權? | n | 拼音 min/max | 字數增量 min/max |
|---|---|---|---|---|
| 音近專名 | 授權 | 6 | 0.400 / 1.000 | +0 / +2 |
| 音近漏字 | 授權 | 1 | 0.800 / 0.800 | +1 / +1 |
| 音近經文 | 授權 | 3 | 0.750 / 1.000 | +0 / +0 |
| 疊字 | 授權 | 3 | 0.667 / 0.667 | -1 / -1 |
| 截斷補全 | 授權 | 2 | 0.500 / 0.500 | +1 / +1 |
| **插入** | 違規 | 4 | 0.250 / 0.500 | **+4 / +6** |
| **語意改寫** | 違規 | 4 | **0.000 / 0.250** | +1 / +3 |
| 事實修正 | 違規 | 4 | 0.333 / 1.000 | +0 / +0 |
| 格式化 | 違規 | 2 | 0.000 / 1.000 | -3 / +0 |
| 潤稿 | 違規 | 2 | 0.000 / 0.500 | -6 / -2 |

**插入**與**語意改寫**各有乾淨的結構特徵；**事實修正**與授權樣本完全重疊。

## 4. 採用的規則與它們的餘裕

```python
MAX_INSERTED_CHARS = 2       # `to` ⊃ `from` 時允許多出的字數
MIN_PINYIN_SIMILARITY = 0.35 # 不帶聲調的拼音編輯相似度
# 外加：casefold 後相同即拒（大小寫聽不出來）
```

| 規則 | 擋到的類別 | 分離的兩端 | 餘裕 |
|---|---|---|---|
| 插入 >+2 字 | 插入 | 授權最多 +1（`未`→`未來`）／違規最少 +4 | 3 個字 |
| 拼音 <0.35 | 語意改寫 | 授權最低 0.400／違規最高 0.250 | **1.60x** |
| casefold 相同 | 格式化（大小寫） | 定義上的分界，無門檻 | — |

**拼音那道的餘裕只有 1.60x，低於 D1／R12 沿用的 2x 判準。**
按既有標準應判「不可用」。仍然採用，理由與代價如下：

- 2x 判準是為**連續指標的分布分離**訂的（R8 的疊加偵測、R12 的 containment）。
  那裡分離不足代表門檻左右都是混合區。這裡不同：實測 31 筆上**誤殺 0**，
  被擋的兩類都是最危險的（插入會憑空增加內容、語意改寫會抹掉講者原話）。
- 代價是**門檻脆弱**。授權側最低的 `意地論`→`瑜伽師地論`（0.400）只比門檻
  高 0.05。這一類（講者口誤吞掉多個字）樣本只有 1 筆，n 不足。
  已知 `波若`→`般若` 只有 0.500——pypinyin 依詞判讀音，同字在不同詞裡讀法不同，
  會壓低分數。這條寫進了單元測試以免日後把門檻往上調時沒發現。
- **累積更多真實校正後應重新校準。** 目前授權側 15 筆中只有 5 筆是實測的。

拼音下限取 0.35 而非 0.40：兩者攔截數完全相同（11/16），
但 0.400 是授權側的最低實測值本身，**取 0.40 等於零餘裕**。

## 5. 效果

| | 放行 | precision | 誤殺授權 |
|---|---|---|---|
| 首跑實際的 9 筆（改之前） | 9 | **0.56** | — |
| 首跑實際的 9 筆（改之後） | 5 | **1.00** | 0 |
| 完整對照組 | 19/31 | 0.79 | **0/15** |

首跑的 4 筆違規全部擋下：

| | 擋它的規則 |
|---|---|
| 陽神為三魂 → 陽神為三魂，動而生也 | 插入（+5 字） |
| 投胎轉世 → 十個月懷胎 | 拼音 0.000 |
| 啟示經 → 創世記 | 拼音 0.333 |
| 沒sense → 沒Sense | casefold 相同 |

`啟示經`→`創世記` 被擋是**巧合不是設計**——它是事實修正，
只是恰好 qi-shi-jing 與 chuang-shi-ji 讀音差夠遠。同類的
`唐朝`→`宋朝`（0.500）就擋不到。這一點寫進了測試的 docstring。

## 6. 擋不到的：事實修正與潤稿

完整對照組上仍有 4/16 違規放行：

| | 拼音 | 為什麼擋不到 |
|---|---|---|
| 唐朝 → 宋朝 | 0.500 | 與授權樣本（0.400–1.000）完全重疊 |
| 六祖惠能 → 六祖慧能 | 1.000 | 同音，結構上與合法的異體字校正無法區分 |
| 三百年 → 五百年 | 0.667 | 同上 |
| 好像很像 → 很像 | 0.500 | 刪贅詞，長度變短，插入規則不管 |

**這不是「還沒做」，是量測後判定程式端做不到。**
「同音但改變事實」與「同音錯字校正」在字串層面沒有可分的特徵——
差別在語意，而語意正是我們不信任模型的地方。

剩下的防線：
1. prompt 的負面示例（已加，見 `understand.py` §3 的「絕對不可以改」）
2. **§5.6 人工抽檢**——這是目前唯一能抓事實修正的機制
3. `text_raw` 永不覆寫（§4.5 約束 3）：校正只寫 `text_corrected`，
   誤改可回溯、可還原。這一條把「錯誤校正」的傷害從不可逆降為可逆。

第 3 點是為什麼這個缺口可以暫時接受。

## 7. 為什麼加回 pypinyin 不等於復活 v0.2 的詞庫鏈

v0.3 移除的是「詞庫 → 拼音 → 候選比對 → **產生**校正」那整條**生成**鏈
（jieba + pypinyin + zhconv），連同 D12 記的繁簡詞頻問題。

這次加回 pypinyin 只做一件事：**驗證模型已經產生的校正是否同音**。
差別在——

| | v0.2 的用法 | R13 的用法 |
|---|---|---|
| 職責 | 決定該改什麼 | 檢查模型宣稱的改動合不合規 |
| 錯了會怎樣 | 產生錯誤校正 | 誤殺或漏放，兩者都可稽核 |
| 依賴 | jieba 詞庫 + zhconv 繁簡轉換 | 無，單純的字→音查表 |

D12 的繁簡問題不適用：查的是**單字讀音**，不是詞頻。

## 8. 重跑方式

```bash
conda run -n pipe-cpu python -m experiments.r13_corrections.measure
```

最後一節直接 import `weft.validation.corrections`，
所以報告的數字與實作不會走鐘。

對照組定義在 `contrast_set.py`，標 `real=True` 者為模型的實際輸出（未經修改）。

**不要為了讓分離度好看而換掉違規樣本。** 事實修正這一類看起來「拖累數字」，
但它是實測到的真實違規形態（`啟示經`→`創世記`），拿掉它只會讓報告好看、
系統不變安全。
