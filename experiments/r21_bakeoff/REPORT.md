# R21：S4a 地端模型選型對打

條件：**R16 的去重架構**（49 張代表幀先經 CV 兩道篩選 → 21 張送 VLM），
同一份 prompt、同一套 schema、`temperature=0.2`、`num_ctx=8192`、JSON 失敗重試 2 次。
硬體：RTX 5070 Ti 16 GB，ollama **0.32.6**（為了 gemma4 從 0.30.2 升級）。

標準答案：`experiments/r14_local_vlm/ground_truth.py`——
**12 張人工繕打**（我開全解析度原圖逐字打的），加 49 張 `is_slide` 人工標註。

---

## 結論（先講）

**沒有單一贏家。兩項工作的最佳模型不同，這正好支持把 S4a 再拆開。**

| | is_slide | slide_text CER（中位） | 中位耗時 |
|---|---|---|---|
| **gemma4:12b** | **95.2%** | 7.7% | 20.3s |
| **qwen2.5vl:7b** | 66.7% | **2.9%** | **1.7s** |
| gemma3:12b | 71.4% | 14.9% | 2.9s |
| qwen3-vl:8b | 84.2%※ | 100%※ | 8.9s |

※ qwen3-vl:8b **在這個環境下是壞的**，不是能力問題，見 §3。

## 1. is_slide：gemma4 大幅領先

| 模型 | 準確率 | 誤報 | 漏抓 | JSON |
|---|---|---|---|---|
| **gemma4:12b** | **95.2%** | **1** | **0** | 21/21 |
| qwen3-vl:8b | 84.2% | 0 | 3 | 19/21 |
| gemma3:12b | 71.4% | 5 | 1 | 21/21 |
| qwen2.5vl:7b | 66.7% | 7 | 0 | 21/21 |

gemma4 只錯 1 張，而且是**零漏抓**——沒有任何真投影片被丟掉。

對照 R16：同樣的去重架構下 gemma3:12b 是 76.2%（那次 21 張的標註與本次
相同，差異在 R16 用 21 張全體、本次同樣 21 張，數字略有出入是因為 R16
把 JSON 失敗計入分母）。**gemma4 相對 gemma3 是世代差距，不是調參差距。**

## 3. qwen3-vl:8b 在這個環境下是壞的

不是能力問題，是相容性問題。三種輸出模式都失敗：

| 模式 | 結果 |
|---|---|
| `format=<schema>` | 吐出 schema **範本**：`{"is_slide": true, "slide_text": "...", ...}`，eval_count 只有 17–25 |
| `format="json"` | content **空字串**，但 eval_count **6654** |
| 不指定 format | 同上 |

`message` 有 `thinking` 欄位——輸出跑到 thinking 通道去了。
加 `think: false` 後 content 仍為空（eval 376）。

**`qwen3-vl:8b` 這個 tag 預設是 thinking 變體**，與 ollama 的 structured
output 不相容。已在背景拉 `qwen3-vl:8b-instruct`，**尚未測**。
表中它的數字**不可用來評斷這個模型系列**。

## 4. gemma4 的兩個觀察

**慢 7 倍**：中位 20.3s vs gemma3 的 2.9s。全片 21 張約 7 分鐘
（gemma3 約 1 分鐘）。仍遠優於 Gemini 的 20 RPD，但不是免費的。

**description 明顯較可信**。同一張內觀經：

- gemma3:12b（R16 §4 記錄）：「右側有綠色邊框，左側有黃色邊框」+ 自創
  「時間、神色、身、能力、漸、音、備等概念」——**編造**
- gemma4:12b：「左側…綠色區塊，內文為『時間軸、色身漸完成』；右側對應
  一個垂直的綠色區塊，內文為『色漸成，功能漸齊備』。在兩個綠色區塊之間
  有一條向左指的箭頭」——**兩個方塊的內容與顏色都正確**

**但這是 n=1 的觀察，不是量測。** `description` 沒有可自動評分的方式
（R12 量到該型別溯源分離度 0.00x），這一欄仍是沒有防護的洞。

## 5. 對架構的意涵

兩項工作的最佳模型不同，這支持**把 S4a 再拆一層**：

```
S4a-1  is_slide           → gemma4:12b（95.2%，零漏抓）
S4a-2  slide_text 轉錄     → qwen2.5vl:7b（中位 2.9%）
                            但英文/多欄版面要退回 gemma4
S4a-3  description        → gemma4:12b（n=1 觀察較可信，未量測）
```

**額外好處**：不同模型分工順帶把 R9 的獨立性補回來——
溯源檢查變成拿一個模型的產出去驗另一個模型讀出的來源。

**代價**：兩個模型不能同時常駐 16 GB（gemma4 7.6 GB + qwen2.5vl 6.0 GB
＝ 13.6 GB，加上 KV cache 會爆）。要嘛分兩趟跑、要嘛接受換模型的載入時間。
**這個成本沒有量過。**

---

## 6. 未量測 / 已知限制

1. **`qwen3-vl:8b-instruct` 沒測**——thinking 變體的問題可能只是 tag 選錯。
2. **`description` 沒有評分方式**。§4 的比較是 n=1 的人工閱讀。
3. **標準答案只有 12 張，且全部來自同一支影片。** 播放清單有 30 支，
   跨集的版面多樣性（經脈圖、臟腑解剖、表格）完全沒進來。
4. **「英文/多欄退回 gemma4」的路由規則沒有實作也沒有量**——
   怎麼判斷一張投影片屬於哪類，本身就是個分類問題。
5. **兩模型輪流載入的成本沒量。**
6. gemma4 在最難那張上**第一次 JSON 失敗、重試才過**。重試已納入量測條件
   （與 S4 的 `with_retries` 一致），但失敗率本身值得留意。

## 7. 重跑方式

```bash
conda run -n pipe-cpu python -m experiments.r21_bakeoff.run     # 產生 out_*.json
conda run -n pipe-cpu python -m experiments.r21_bakeoff.score
```

`run.py` 會續跑（已有結果的跳過）。要重測某個模型就刪掉它的 `out_*.json`。
需要 ollama ≥ 0.32 才拉得到 gemma4。
