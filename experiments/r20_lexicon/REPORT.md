# R20：詞庫該不該建、該建在哪一層

> ## ⚠️ 2026-08-08 更正（R32／票 10）
>
> 下面「ASR 解碼**沒用**」的結論**只對一半**。正確的寫法是：
> **「整支影片建一個全域 200 字經文 prompt」這個做法沒用**。
>
> 換成 DocWhisper 的做法——**逐段只餵當下那張投影片**——之後：
>
> | | 術語命中 | CER |
> |---|---|---|
> | 無 prompt | 6/20 | 0.143 |
> | 全域 200 字（本實驗） | 5/20 | 0.132 |
> | **逐段** | **9/20** | **0.113** |
>
> 差別不在插入點，在**粒度**。全域 prompt 把整支影片的術語混在一起餵給
> 每一段，等於在每一段都加入大量與當下無關的詞——那是雜訊不是提示。
>
> 見 `experiments/r32_local_prompt/REPORT.md`。


提問（使用者）：這些術語多半來自經典與文言文，一般語言模型不具備這些知識，
是不是該建一個詞庫？

**方法**：不辯論，量兩個插入點——ASR 解碼（`initial_prompt`）
與事後校正（拿詞庫掃 ASR 輸出）。

素材：`zIglvjoU9vo`，人工字幕為標準答案
詞庫來源：**只用 `slide_text`**——那是無字幕影片唯一拿得到的東西

---

## 結論（先講）

**該建，但不是建在你可能以為的那一層。**

| 插入點 | 實測 | 判定 |
|---|---|---|
| **ASR 解碼**（Whisper `initial_prompt`） | 術語 4/19 → **5/19**，CER 12.3% → 12.0% | **沒用** |
| **事後校正**（詞庫掃 ASR 輸出） | 拼音門檻 0.90 下 **precision 90%**，抓到 **14 個相異錯誤** | **可用** |

而且「模型不懂這些詞」這個前提**只對了一半**——見 §1。

---

## 1. 前提檢查：模型其實懂，只是聽錯

反例來自既有資料：

- **R13 那一輪，VLM 自己提出** `意地論 → 瑜伽師地論`、`憍梵钵提 → 憍梵波提`。
  **它知道這些詞。**
- Whisper 把 `太上老君內觀經`、`阿賴耶識`、`陽神`、`陰靈`、`業力`、
  `三魂`、`七魄` 全寫對了。
- Gemini 讀投影片上的經文 CER 只有 10.1%，扣分主要在漏掉直排側欄。

錯的集中在 `識蘊`／`五蘊`／`憍梵波提`／`瑜伽師地論` 與整段經文。
這比較像**聲學層的解碼偏好**，不是知識缺口——`五行分藏` 與 `五行分障`
同音，模型選了常見的那個。

這個區分決定了詞庫該放在哪一層。

---

## 2. ASR 解碼：實測沒用

從 `slide_text` 建 200 字的 `initial_prompt`（經文優先，見 §5）：

```
一月為胞，精血凝也。三月陽神為三魂，動而生也。四月陰靈為七魄，靜鎮形也。
五月五行分藏，以安神也。六月六律定腑，用滋靈也。七月七精開竅，通光明也。…
```

同模型、同參數，只差有沒有 prompt：

| | 術語正確 | 整體 CER |
|---|---|---|
| 無 prompt | 4/19 | 12.3% |
| **有 prompt** | **5/19** | **12.0%** |

修好 `陽神為三魂`、`中陰身`；**弄壞 `阿賴耶識`**（原本是對的）。

**經文原句一字不差放在 prompt 裡，Whisper 還是寫 `五行分障`。**

原因推測：`initial_prompt` 在 faster-whisper 中只作為第一個視窗的前文，
影響力在 42 分鐘的轉錄過程中迅速衰減。**未進一步驗證這個推測。**

這一項與 known-risks **R11**（v0.3 移除 `initial_prompt` 詞庫）的結論一致，
但理由不同：R11 記的是「詞庫來源（本地 OCR）被移除了」，
實測顯示**就算把來源補回來，這個插入點本身也沒有效果**。

## 3. 事後校正：可用，precision 90%

作法：從 `slide_text` 抽 2–5 字的中文片段當詞庫（1734 個），
取其中 ASR 沒寫出來的（1017 個），在 ASR 輸出上滑窗找**拼音最相近**的片段，
超過門檻就產生校正候選，再交給 **R13 既有的三道閘**驗證。

| 拼音門檻 | 候選 | 判對 | precision |
|---|---|---|---|
| 0.70 | 120 | 60 | 50% |
| 0.80 | 71 | 56 | 79% |
| **0.90** | 61 | 55 | **90%** |
| 1.00 | 61 | 55 | 90% |

**0.90 與 1.00 完全相同**——0.9 以上的候選實際上都是完全同音。
誤報全部集中在 0.70–0.80 那一段（`潢房子是`→`同房子是` 這類無意義的窗）。

候選之間有大量重疊的 n-gram。去重後是 **14 個相異錯誤**：

```
天地夠精 → 天地媾精      陰陽不化 → 陰陽布化
萬物已生 → 萬物以生      人壽其生 → 人受其生
雪寧也   → 血凝也        異導氣   → 意導氣
月六律定府 → 月六律定腑   月七經開竅 → 月七精開竅
月八經神聚 → 月八景神具   月功事羅布 → 月宮室羅布
八月八經神 → 八月八景神   運開始進入 → 蘊開始進入
緣和補時 → 元和哺食      閱以前   → 月以前
```

**對照組：VLM 在人工字幕上只產生 7 筆校正。**

`precision = 90%` **恰好**踩在 §5.2 的門檻（術語校正 precision ≥ 0.90）
上，**沒有餘裕**。

---

## 4. 這改變了什麼

詞庫的價值不在「教模型認字」，在**提供一個獨立的比對基準**——
和 §5.4 溯源的邏輯一樣。它把「模型有沒有主動注意到」這個不可靠的環節，
換成「程式逐一掃過詞庫」的窮舉。

三個可能的用途，本報告只量了第一個：

1. **事後校正的候選產生器**（已量，precision 90%）
2. **R19 交叉檢查的術語清單**——目前只有 53% 覆蓋率，詞庫可補
3. **具名實體檢查的白名單**（R7 記的人名缺口）

---

## 5. 限制與未量測

1. **詞庫只涵蓋投影片提到的詞。** R19 量過：72 個術語只有 38 個（53%）
   在 `slide_text` 中。`投胎轉世`、`中陰身`、`五蘊` 這些只在口述中出現的，
   詞庫抓不到。**這是本方案最大的缺口。**
2. **precision 90% 沒有餘裕**，且「判對」的認定是程式化代理
   （正確寫法在人工字幕中、錯的不在），不是人工逐條確認。
3. **n-gram 重疊**讓「61 筆候選」看起來比實際多——相異錯誤只有 14 個。
4. **`initial_prompt` 失效的原因未驗證**（推測是影響力衰減）。
   若換用 `condition_on_previous_text` 或分段餵 prompt 可能不同。
5. **跨影片累積的詞庫沒有測。** 系列的第 2 集可以用第 1 集的投影片術語，
   這會讓覆蓋率隨集數上升——但 §1 的前提（同系列術語重疊）沒有量過。

---

## 6. 重跑方式

```bash
conda run -n pipe-cpu python -m experiments.r20_lexicon.build_prompt   # 建 initial_prompt
conda run -n pipe-gpu python -m experiments.r20_lexicon.run            # 帶 prompt 跑 Whisper
conda run -n pipe-cpu python -m experiments.r20_lexicon.measure        # A/B 術語與 CER
conda run -n pipe-cpu python -m experiments.r20_lexicon.post_hoc       # 事後校正的 precision
```

需先有 `experiments/r17_whisper/whisper_cues.json`（無 prompt 的對照組）。

**`build_prompt.py` 的優先序是啟發式的**——不排序的話 prompt 會被講者簡歷
（「行政院國家發展基金視訪委員」）塞滿，經文只進得去一半。
換素材時這個啟發式要重看。
