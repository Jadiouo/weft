2026-08-09。**負面結果。** 記下來是為了不要再試同一種措辭。

| | |
|---|---|

## 1. 要解的問題（R40 的後果）

把 `depth_alpha` 從 −0.5 調到 +0.75，分段品質大幅改善，
但 `2FjApOVIbUs` 的**總產出字數掉了 47%**，而溯源通過率反而升到 1.000。

機制：**S4c 每段產出的 block 數與段落長短無關**（實測 1.2–1.9 個），
prompt 從頭到尾沒有規定過。段數砍半 → 內容砍半。

## 2. 改了什麼

v8 只加一條規則，**其他一個字都沒動**（D31 的教訓：v6 那次改太多，
把 qwen2.5:14b 帶偏到 0 個 content_block）：

```
7. **把這一段講到的東西都寫出來，不要只寫一兩點。** 段落有長有短——
   長的段落本來就該產出比較多 content_block。判準不是「幾個」，
   而是「這一段裡還有沒有讀者會想查到、但你還沒寫的東西」。

   一段三分鐘的講解濃縮成兩句話，等於把其餘的內容丟掉了；
   那些內容不會再有第二次機會被寫進知識庫。
```

## 3. 結果

每千字逐字稿產出的字數：

| 影片 | v7 | v8 | 變化 |
|---|---|---|---|
| `cxrqHABhWOU` 調校 | **464.6** | **233.3** | **−50%** |
| `2FjApOVIbUs` 保留 | 361.8 | 364.1 | +0.6% |
| `UiKi5-Arce4` 保留 STEM | 713.0 | 745.7 | +4.6% |

`UiKi5-Arce4` 的溯源通過率也從 0.866 升到 0.915——**那是 v8 唯一的
實質好處**，但它換不回調校集腰斬。

### 3.1 模型做了什麼

| | block 數 | 總字數 | 每 block 字數 |
|---|---|---|---|
| `cxrq` v7 | 12 | 1386 | **115** |
| `cxrq` v8 | 11–15 | 684–738 | **~50** |
| `2Fj` v7 | 27 | 1848 | 68 |
| `2Fj` v8 | 34 | 1860 | 55 |

**兩支都是「block 變多、每個變短」**，總量沒增加甚至大減。
prompt 說的是「不要只寫一兩點」，模型理解成「多列幾點」，
而不是「寫得更完整」。

## 4. 為什麼敢說不是雜訊

`temperature = 0.2`，**沒有 seed**，所以模型不是確定性的。
n=1 不能下結論——這是 R23／R37 已經栽過兩次的地方。

清掉快取重跑同一個設定三次：

```
v8 run1: 11 block、696 字
v8 run2: 13 block、684 字
v8 run3: 15 block、738 字
```

**跑次變異 ±4%**（684–738）。而 v7 是 **1386 字**——
效果量是變異的十倍以上。

> 值得記的是 block 數的變異（11／13／15）比字數大得多。
> **拿 block 數當指標會比拿字數更容易被雜訊騙。**

## 5. 已退回，但保留的東西

退回 v7（prompt 文字、`prompt_version`、測試雜湊、兩個 yaml）。

**保留**：
- `content_yield()` 與 `provenance.jsonl` 的產出量欄位
- `MIN_CHARS_PER_1K_SOURCE = 100` 的災難下限

它們是**讓這件事看得見的東西**，本身沒有問題——
沒有它們，v8 的損失和當初 α 造成的 47% 一樣會悄悄過去。

## 6. 下一個人不要做的事

- **不要再用「把內容都寫出來／不要只寫一兩點」這類措辭。**
  qwen2.5:14b 對它的反應是「多列幾條短的」。
- **不要拿 block 數當產出量指標**（變異 ±18%，字數只有 ±4%）。
- **不要只跑一次就下結論**——`temperature=0.2` 且無 seed。

## 7. 還沒試的方向

- **給長度下限**（例如「每個 content_block 至少 80 字」）。
  風險：模型會灌水湊字數，而溯源檢查對灌水的抵抗力未知。
- **按段落長度給明確配額**（「每 60 秒逐字稿至少一個 block」）。
  風險：把數量寫死回到 v6 的老路（D31）。
- **不改 prompt，改成兩段式**：先列大綱再逐點展開。
  代價是呼叫次數加倍。

三個都**未評估**。

## 8. 限制

- **三支影片，其中只有 `cxrqHABhWOU` 做了重複量測。**
  `2Fj` 與 `UiKi5` 的 v7／v8 各只有一次。
- 變異只量了 v8，**沒有量 v7 的變異**——所以「1386 vs 690」的比較裡，
  v7 那一邊是 n=1。效果量夠大，但嚴格說這個對照不對稱。
