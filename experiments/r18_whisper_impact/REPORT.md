# R18：Whisper 逐字稿對下游的實際影響（量測，非推論）

起因：R17 實跑 Whisper 後，我提出兩個「硬問題」——繁簡會讓溯源結構性崩潰、
術語錯誤 R13 補不上。**兩個都是推論，沒有量。** 這份報告把它們量出來。

素材：`zIglvjoU9vo`（人工字幕當標準答案）＋ R17 的 Whisper 輸出

---

## 結論（先講）

**我推論的兩個問題，量出來都不成立。**

| 我說的 | 實測 |
|---|---|
| 繁簡會讓 §5.4 溯源「結構性崩潰」 | **掉 5.6 個百分點**，而且一行 opencc 就修掉 |
| R13 補不上 ASR 的術語錯誤，吞字型會被程式端主動擋掉 | 程式端**放行 14/14 = 100%** |

換掉逐字稿來源的總代價：溯源通過率 **98.6% → 97.2%**（轉繁後），
純辨識錯誤只值 **1.4 個百分點**。

**剩下真正沒量的只有一件事**：VLM 看到 Whisper 逐字稿時，
會不會**主動提出**那些校正（recall）。那需要花配額。

## 1. R13 的能力上限：100% 放行

`align.py` 以時間重疊對齊兩份逐字稿，讀出 Whisper **實際**寫成什麼
（不臆測），得到 14 組真實錯誤對。對每一組問：
**假設 VLM 完美地提出了正確校正，R13 的程式端會不會放行？**

| Whisper 寫的 | 正確 | 拼音 | 長度差 | R13 |

| 攝受想行事 | 色受想行識 | 0.80 | +0 | 放行 |

| 餘邪師弟論 | 瑜伽師地論 | 0.80 | +0 | 放行 |
| 異地論 | 瑜伽師地論 | 0.40 | +2 | 放行 |

| 行造胚也 | 形兆胚也 | 0.75 | +0 | 放行 |
| 五行分障 | 五行分藏 | 0.75 | +0 | 放行 |
| 六律定府 | 六律定腑 | 1.00 | +0 | 放行 |
| 七經開竅 | 七精開竅 | 1.00 | +0 | 放行 |

**14/14 放行。**

我原本斷言「`七精開竅`→`七經` 這種吞字，拼音相似度會很低，會被程式端主動
擋掉」。**那個例子是我編的**——Whisper 實際寫的是 `七經開竅`（拼音 1.00），
不是 `七經`。ASR 的錯誤幾乎全是**等長的同音替換**，正好落在 R13
設計的授權範圍正中央。

R13 的門檻是拿**真實的違規樣本**校準的（R13 §2），
而 ASR 錯誤與那些違規（事實修正、語意改寫、插入）在結構上完全不同。

**仍未量**：VLM 的 recall。這是「上限」不是「實測 recall」——
模型還得先注意到錯誤、且知道正確寫法。要花配額。

## 2. 繁簡與辨識錯誤各值多少：5.6 與 1.4 個百分點

固定既有的 70 個 content_block，只抽換溯源比對的來源文字，跑同一套
`check_block` + 型別級 copy_ratio 後處理（與 `check_video` 一致）：

| 組別 | 溯源通過率 |
|---|---|
| A 人工字幕（現況基準） | **98.6%** |
| B Whisper 原樣（簡體） | **91.5%** |
| C Whisper 轉繁（s2twp） | **97.2%** |

逐型別：

| 型別 | A | B | C |
|---|---|---|---|
| 經文原文 | 15/15 | 15/15 | 15/15 |
| 白話解說 | 15/15 | 12/15 | 14/15 |
| 口頭延伸 | 29/29 | 27/29 | 29/29 |
| 圖表描述 | 11/12 | 11/12 | 11/12 |

- **繁簡（C−B）＝ +5.6%**
- **辨識錯誤（C−A）＝ −1.4%**

經文原文三組都是 15/15——它們引 `slide_ocr`，換逐字稿不影響，
這也反證了實驗確實只動到該動的變因。

### 為什麼我原本的推論錯了

我說「簡體逐字稿對繁體投影片，bigram 重疊會結構性崩潰，與 R12 量到的
跨語言必為 0 是同一個機制」。錯在兩點：

1. **繁簡不是跨語言。** 中文簡繁之間有大量共用字，bigram 重疊只是變稀疏，
   不是歸零。R12 那個 0.000 是英文投影片對中文描述，字集完全不交集。
2. **口頭延伸的來源就是逐字稿本身。** block 與來源同源時，
   來源用哪個字集其實不影響兩者的一致性——實測 29/29 全過。

**注意這個實驗是最壞情況**：block 是從**繁體**人工字幕產生的，
拿去比對簡體來源，正是字集不匹配的極端。真實情況下 VLM 看到簡體逐字稿
可能連 block 也寫簡體，落差會更小。

## 3. 這改變了什麼

繁簡是**一行 opencc 的工程問題**，不是設計問題：

```python
# S1a 策略 2 之後
cues = [(a, b, OpenCC("s2twp").convert(t)) for a, b, t in cues]
```

值 5.6 個百分點，且沒有副作用（人工字幕本來就是繁體，轉換是 no-op）。
`s2twp` 而非 `s2t`——它會一併處理台灣用詞（`鼠標`→`游標`）。

術語錯誤則**不需要新機制**：R13 已有的閘全部放行，
缺的只是「VLM 會不會提」——而那是 prompt 與 recall 的問題，
不是要不要把 v0.3 移除的詞庫請回來（R11）的問題。

**在量到 VLM recall 之前，不應該動詞庫。**

## 4. 仍未量測

1. **VLM 對 Whisper 逐字稿的校正 recall。** 需配額。這是唯一剩下的未知。
2. **策略 3（雙重驗證）** ——`zIglvjoU9vo` 沒有自動字幕，得另找素材。
3. **12.4% CER 對 `content_block` 內容品質的影響。** 本報告量的是
   「溯源找不找得到依據」，不是「產出的內容好不好」。後者需要人工評讀。
