## 2. 問題一：投影片是英文，語音是中文——S4b 的詞庫變成空的

```
slide_text: "NCU - Human and Machine lab  1 Chapter 2 – Spatial Representation…"
            "Four Angle Rotation  Three Angle Rotation for Euler angles…"

詞庫： jgVD7IPNTs8 0 詞 ／ UiKi5-Arce4 2 詞 ／ xBfyWwYylSA 0 詞
校正： 三支都是 0 筆
```

S4b 從 `slide_text` 建詞庫（D25），隱含假設**投影片與語音同語言**。
中文授課配英文投影片在台灣的大學課程是常態，而這個組合下
整個 S4b 產不出任何東西。

**不是壞掉，是假設不成立。** 沒有現在就改——要改得先決定
「英文術語該不該用來校正中文 ASR」，而那不是一個實作問題。

## 4. 問題三：S4c 會**默默修好 ASR 的錯字**，而那不算在任何一種成因裡

`UiKi5-Arce4#014`，相似度 0.039：

```
block 寫的：  「坐標系B中的點P轉換到坐標系A」「4x4 的矩陣」
逐字稿 raw：  「這個做法系統…它有一個原點…有一個位置叫PB」
```

Whisper 把「**座標**」聽成「**做標**」（等長同音，正是 R18 描述的形態），
而 S4c 在寫 block 時**自己改對了**。

溯源對 `transcript_raw` 比對因此失敗——**那個判定是對的**，
那些字確實不在原始逐字稿裡。但成因被歸到「兩個來源都對不上」，
而實情是「模型悄悄修好了 ASR 的錯字」。

`depends_on_correction`（票 01）抓不到它，因為那個校正
**發生在模型腦裡，不在 `Correction` 清單上**。R28 設計那個機制時
假設校正都經過 S4b 並留下紀錄。

> 這是三分法之外的第四類。目前它被算進「真的溯不到」，
> 而那一欄正是拿來判斷「內容有沒有問題」的——**混進去會高估內容問題**。

**沒有現在就改**。要分辨它需要「這兩個詞是不是同音」這種判斷，
而那正是 R13 的拼音比對在做的事——把它接到溯源診斷上是可行的，
但要先量它會不會製造誤報（D25 的教訓：在錯誤基率高的資料上量出的
precision 會虛高）。

另外一半是**數學符號**：模型把口說的「四乘四」寫成 `4x4`、
把「R 一一」寫成 `R₁₁`。字元 n-gram 對這種正規化完全無能為力。
STEM 素材上這會是常態，不是偶發。

## 5. 順帶驗證的東西

- **票 04 的單一模式豁免**在大问题上生效（分離度 1.54x 遠低於 3.0，
  但全螢幕 2.4% → 跳過該判準）。舊邏輯會直接擋下純口播影片。
- **票 05 的跨集前濾**在機器人學上有 4 支參考可用（含中醫講經），
  沒有誤殺——但也幾乎沒剔除，因為兩批素材的畫面差太遠。
- **S1c 的去重比例差異很大**：課程介紹 6/6（全部相異），
  單元二 85/117 與 59/91。投影片型教學的重複率遠低於中醫講經
  （那邊是 22/49）。`distinct_ratio` 作為 profile 項目在這裡有意義。

## 6. 限制

- **抽 3 支，不是 26 支。** 這些數字不能推廣到整個播放清單——
  單元二那兩支是同一個單元，內容高度相關。
- 沒有人工字幕，**CER 算不出來**。溯源保證的是「chunk 沒有編造
  Whisper 沒說的話」，不是「Whisper 聽對了」。
- 沒有為這批素材做黃金集標註，所以分段品質**沒有量**。
