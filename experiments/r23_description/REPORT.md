# R23：`description` 的把關訊號——多模型一致性

**背景**：R16 §4 記的洞——`description` 會編造，而 R12 量到 `圖表描述`
型別的溯源分離度是 **0.00x**，現有機制一個都抓不到。這是 v0.4 提案
§11 列的新風險第 6 項，SDD §9 也記著。

**假設**（沿用 R19 的作法）：多個模型各自描述同一張投影片，
**編造處各說各話，真實處會一致**。

---

## 結論（先講）

**一致性有鑑別力，分離 13.59x。**

| | 平均被幾個模型提到（共 3） | n |
|---|---|---|
| 事實主張 | **1.81 / 3** | 16 |
| 編造主張 | **0.13 / 3** | 15 |

判準比照 D1／R12（<2x 即不可用），**13.59x 遠高於門檻**。

**但這是手寫對照組，且我在過程中標錯了一項**——見 §3。

---

---

## 2. 這解決了什麼

R16 記的那個具體編造——gemma3 把內觀經的兩個綠色方塊說成
「右側綠色、左側黃色」並自創「概念對應」——在這個訊號下會被抓到：
「黃色」只有 1/3、「表格」只有 1/3，而「綠色」是 3/3。

實跑中 gemma3 對 slide_029 的描述也編造了「從紅色到黃色再到綠色」的
漸變與「對照表格」結構，同樣只有它一個人這麼說。

## 3. 過程中我標錯了一項——而它偽裝成「訊號沒有鑑別力」

第一版把 `slide_045`（黃底三月陽神）的「藍色」列為**編造**。
結果它被 **2/3** 個模型提到，把編造組的平均從 0.13 拉到 0.25，
分離度從 13.59x 掉到 7.20x。

回頭開原圖看——**右側解剖圖裡的胚胎確實是藍紫色的環狀構造**。
是我看漏了，不是模型編的。

**這件事本身比數字重要**：對照組出錯時，它不會長得像「對照組錯了」，
它會長得像「這個訊號沒那麼準」。若我當時就接受 7.20x 並開始調參數，
就會在錯的方向上優化。

**唯一的防線是回去看原始素材**，而不是看數字合不合理。

## 4. 限制（這份量測撐不起的結論）

1. **對照組是我手寫的，只有 4 張投影片、31 個主張。**
   「哪些算編造」由我判定，而 §3 證明我會判錯。
2. **「編造」的候選是我列的，不是模型實際說過的全集。**
   我列了一些通用的錯誤結構（表格、長條圖），模型本來就不太可能說。
   真正嚴格的作法是把三個模型說過的**所有**主張抽出來逐條人工判定——
   那才是無選擇偏差的作法，本次沒做。
3. **沒有實作。** 要用起來需要「從描述中抽出可比對的主張」，
   而那本身是個 NLP 問題。目前只證明訊號存在。
4. **三個模型都是 VLM，且都在同一台機器上跑同一張圖。** 共享的錯誤模式
   （例如都看錯同一個顏色）不會被這個訊號抓到——與 R19 的同家族問題一樣。

## 5. 建議的用法（未實作）

不做逐條主張比對，改用最粗但可實作的版本：

**同一張投影片跑兩個模型，描述的相似度低於門檻時，
把該張標記為 `needs_review`，不阻擋產出。**

理由：§5.4 對 `圖表描述` 已經確定沒有自動閘門可用（0.00x），
所以這裡的目標不是「擋下來」，而是**把 §5.6 的人工抽檢引導到最可能出錯的
那幾張**。目前人工抽檢沒有任何優先序，等於全片平均分配注意力。

**成本**：每張多一次本地呼叫。S1c 之後全片只有 ~22 張代表幀，
以 gemma3 的 2.9s 計約多 1 分鐘。
